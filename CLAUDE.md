# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

AnywhereLLM is a Flutter chat client for Android phones for an AnythingLLM server. It shows workspaces and their chats (each workspace's Main chat and its AnythingLLM threads), streams answers, and manages each workspace's documents, instructions and answer settings in the workspace's pages. It shows an answer that finished out of sight as an Android notification. It keeps the server address and API key in the Android Keystore and its other preferences in a JSON file. It calls AnythingLLM's own API, and nothing else, directly, over https or over plain http on a private network (below); there is no backend of its own.

**This is the `lite-stock` branch**: a build for plain, unmodified AnythingLLM. It has none of master's toolkit (anywherellm-bridge) or suite features: no companion server is probed, paired with or stored, and there is no Memory, Upcoming, toolkit card, Add the toolkit guide, apps-lean/Library/Vault pages, agent's browser or tabs sheet, and no page web view. Every request goes to AnythingLLM's own developer API (and an answer's images on its host). It installs beside Lite as `local.anywherellm.lite.stock`, labelled `Lite (stock)`.

## Commands

```bash
flutter pub get
flutter analyze
flutter test                                   # whole suite; fakes the server and the keyring
flutter test test/ui/shell_test.dart           # one file
flutter test --plain-name 'a new server starts afresh'   # one test by name
flutter run -d <android-device>                # a phone over adb, or an emulator
flutter build apk --debug                      # -> build/app/outputs/flutter-apk/app-debug.apk
flutter build apk --release                    # needs android/key.properties
flutter test tool/store_graphics.dart          # store graphics -> build/store/en-US, or $STORE_GRAPHICS
flutter test tool/screens.dart                 # each screen at 390x844 and the wide ones at 1440x900 (desk-*), light and dark -> build/screens, or $SCREENS
uv run tool/audit/audit.py                     # walk the app on an emulator over the test fakes, light and dark -> build/audit/*.zip; `--help` lists the options
uv run tool/parity/parity.py --help            # Muse parity test harness: docs/protocols/muse-parity-process.md
```

A release APK is signed with the key named in `android/key.properties` (gitignored), which the personal F-Droid repo's `appstore sync` writes the first time it builds the app. Without that file the release build fails rather than signing with the debug key, because every later update must carry the first release's key. `android.enableResourceOptimizations=false` keeps the launcher icon at the path fdroidserver reads, and `allowBackup` is off so a restored backup never carries a Keystore-encrypted key to a device that cannot decrypt it. Its launcher icon is Shane's RX1, whose sources are in `assets/icon` (its README says what each file is): the adaptive icon (`mipmap-anydpi-v26`, with a monochrome layer for themed icons), the launch screen's robin (`drawable/splash_robin.xml`, on #343FA9 in light and dark mode, through `values-v31`/`values-night-v31` and every `launch_background.xml` before Android 12) and the notification icon are the pack's vector drawables, used as they came, and the legacy `mipmap-*dpi/ic_launcher.png` for Android 7 are rendered from `assets/icon/anywherellm-icon.svg`. Nothing generates them; a new icon replaces those files by hand. The in-app logo is still drawn by the robin mark (`RobinMark`, `lib/ui/widgets/robin_mark.dart`, in `iconGround` and `iconInk`). It needs the Android SDK; `minSdk` is Flutter's default (24), which is what `flutter_secure_storage` requires.

The F-Droid store page's feature graphic and phone screenshots come from `tool/store_graphics.dart`, which draws them with the app's own fonts over the test fakes, so no real server shows; copy `build/store/en-US` to `metadata/local.anywherellm.lite/en-US` in the app_store project (its `phoneScreenshots` replaced whole, since the store lists every file there, and its `icon.png` kept, since the tool does not draw it), whose `appstore.toml` holds the listing text, and run `appstore sync` there.

The Dart package is `anywherellm`, so imports are `package:anywherellm/...`. The repository folder is still `everything`.
- On `lite-stock` the launcher label is `Lite (stock)`, the application ID `local.anywherellm.lite.stock` and the version `1.19.3-stock`, so it installs beside Lite with a keyring of its own; both claim `anywherellm://connect` links, so Android asks which opens one.
- `flutter_secure_storage` keys its keyring entry by the application ID. Changing `applicationId` orphans any saved key.

## Architecture

Imports run `ui -> core <- adapters`. `lib/main.dart` is the only file that knows both sides. `test/layers_test.dart` enforces this with substring checks on import targets:

| Layer | May not import |
| --- | --- |
| `lib/core` | Flutter, `dart:io`, `dart:ui`, `http`, `flutter_secure_storage`, `file_picker`, `mobile_scanner`, `ui`, `adapters` |
| `lib/adapters` | Flutter, `dart:ui`, `file_picker`, `mobile_scanner`, `ui` |
| `lib/ui` | `dart:io`, `http`, `flutter_secure_storage`, `adapters` |

**Core** holds the ports (`core/ports.dart`: `AnythingLlmApi`, `SettingsStore`, `PrefsStore`), the server models (`core/server_models.dart`: `Workspace`, `Thread`, `ChatMessage`, `Citation`, `WorkspaceDoc`, `LibraryDoc`, `LibraryFolder`, `DocEntry`, `SearchHit`), and the pure logic, one file per concern: `chat.dart` (events, modes, titles, attachments, `openableLink`, `loadableImage`, status lines, `modelFailure`, `refusesPictures`, `splitReasoning`), `files.dart`, `json.dart`, `outputs.dart` (generated files, answer metrics), `system_settings.dart`, `providers.dart` (`Provider`, a chooser's value with its name and, for a chat provider reached at an address, the setting that holds it; the choosers; the lines Privacy and data shows), `chat_groups.dart`, `sources.dart`, `prefs.dart`, `find.dart`, `markdown.dart`, `gallery.dart`, `upload.dart`, `connection.dart` (`keySafe`, `isPrivateHost`, `parsePairingCode`, and `isLoopback`, which `chatModelPrivacy` reads as the server's own machine, with `host.docker.internal` besides), `copy.dart`, `users.dart` (`ServerUser`, someone with an account on a multi-user server, and `WorkspaceMember`, one a workspace lists: `ServerUser.opens` says whether they open a workspace, which an admin and a manager always do). Every failure is an `ApiException(message, {status})` (`core/errors.dart`); `NotConfigured` is the subtype thrown when no server is set up, and `CutOff` the one for a streamed answer whose connection dropped or fell silent after the server took the question. To run calls at once, use `Future.wait` on futures that catch their own errors: the record `.wait` wraps errors in `ParallelWaitError`, which breaks the `on ApiException` handlers.

**The connection** lives in one shared `ConnectionHolder`, built in `main.dart`. `HttpAnythingLlmApi` reads it on every call, so a saved connection takes effect without a restart. `SettingsController` is the only writer, through `load`, `save`, `clear` and, after `verify`, `connect` and `pair`, which notify listeners. `ChatController` listens and starts afresh when the connection changes; `SessionHost` builds it before reading the keyring, so reading a saved connection is what loads the workspaces. It, `FilesController` and `SystemController` follow the server through `FollowsServer` (`ui/state/follows_server.dart`): another connection, compared as one (`serverKey`), runs `leavingServer`, where `ChatController` sends a delete waiting to be undone, then `serverChanged`; a call takes `here`, a `ServerAt`, before it is sent, and keeps its answer only while `current` holds (the same connection in use, though another came between), or `unchanged` (nothing it follows has changed, even and back). `verify(Connection)` takes an explicit connection so Settings can test one before saving; `SettingsController.connect` verifies first and saves only on success. A test's answer that arrives after another test began, or after the connection in use changed, is dropped.

**https, or http on a private network.** Dart's `HttpClient` ignores Android's cleartext policy, so the app keeps its own rule (`keySafe`, `isPrivateHost` in `core/connection.dart`): the key goes over https anywhere, and over plain http only to a private host: `localhost`, a name with no dot that is not a number, a name under `.local`, `.lan`, `.home.arpa` or `.ts.net`, an IPv4 address in `127/8`, `0.0.0.0`, `10/8`, `172.16/12`, `192.168/16`, `169.254/16` or Tailscale's `100.64/10` written as four plain decimal parts (a resolver may read `134744072`, `010.0.0.1` or `10.1` as a public address, so none counts), or IPv6 `::1`, `fc00::/7` or `fe80::/10` with the first group written in full (`fd00::1`, not `fd0::1`); an empty host name (`.`) is not private. `normalizeBaseUrl` refuses any other http address (`plainHttpRefused`) and a host name of anything but letters, digits, dots, hyphens and underscores (a name outside ASCII is percent-escaped by `Uri.parse` and no resolver finds it; its `xn--` form is taken). Every call and `verify` check the address again before the key is sent (`_secure`), and the same rule decides an answer's image; the manifest's `usesCleartextTraffic` lets the in-app browser load such a page. A saved http connection (`Connection.plainHttp`) shows a Plain http warning on the Connection page, and the pairing sheet shows one for each http address a link names (`plainHttpWarning`): the key goes unencrypted to whatever answers that host on the network the phone is on, which on another Wi-Fi, or on mobile data with Tailscale off, can be another machine.

**Scanning a pairing code.** Scan QR code on Settings' Connection page reads a code another AnywhereLLM drew, `anywherellm://connect?url=...&key=...`, with `AppScope.scanner`; the code shows in Connect to this server? (`PairingSheet`, through `ShellController.showShared`) as a tapped link does, since a code on a sticker can name any server, and the sheet says why when `parsePairingCode` refuses it; a pairing link pasted in the address field, the first run's or Edit connection's, shows there too once Connect or Save key is pressed, and the key field is not read; its Connect hands it to the Connection page (`ShellController.pairWith`), which saves it through `SettingsController.pair`. Nothing of a code is put in the form, which goes back to the saved connection (`_backToSaved`) whether it paired or not, so a key typed after a failed code never goes to the address it named; why it failed shows under the form. The scanner is `cameraScanner` (`ui/settings/scan_code.dart`, `mobile_scanner`), imported by `main.dart` only; tests pass a fake or null, and with none there is no Scan button. The camera shows in `ScanView` (`ui/settings/scan_view.dart`), a page over the window under Back, heard as Cancel, with the camera in a square as wide as the page's content, where to find the code and How connecting works; whether it is open is `ShellController.scanning`, which Esc and Back stop first. `mobile_scanner` bundles Google ML Kit (`libbarhopper_v3.so`, not free software) and adds about 17 MB to the release APK; its manifest adds the CAMERA permission with the camera marked optional.

**Dictation.** The composer has a microphone where there is `AppScope.dictation`; while it listens the button is Stop dictating, a stop mark (Lucide's circle-stop, `stopCircle`) in `onAccent` on the `accent` (`IconBtn(solid:)`), not the microphone tinted. `Dictation` (`ui/chat/dictation.dart`) is the port: `start` gives the words heard so far in full each time and calls `onDone` once when listening ends, with the `DictationEnd` that ended it: `stopped` by `stop`, `paused`, or `failed`. `SpeechDictation` (`ui/chat/speech_dictation.dart`, `speech_to_text`) is imported by `main.dart` only. What is heard follows the message as it stood when listening began. A change to the message made otherwise, by typing, a shortcut or Edit, ends the go and is kept. Sending ends the go, and words that arrive after it are dropped. `done` ends a go, not `notListening`, which comes before the last words. `SpeechDictation` gives each go its own id, and `start` waits for a stop in flight, so the `done` that stop brings never ends the next go. With `ChatSwitch.sendDictation` on, a go that ended `paused` after it heard words sends the message when `ChatController.canSend` allows it, the same check the Send button and `send` itself make; a pause that heard nothing, a go the person stopped and one that failed leave the message in the box. The manifest adds `RECORD_AUDIO` with the microphone marked optional and a `queries` entry for `android.speech.RecognitionService`; recognition runs in the device's own service, which may send the audio to its maker.

**The developer key alone.** The app reaches AnythingLLM through its developer API (`/api/v1`) with the developer key, and never signs in to the web UI. What only the web login opens (`validatedRequest`: deleting a thread's exchanges, marking an answer, saved memories, scheduled jobs, AnythingLLM's own web push, developer keys, slash-command presets) the app leaves alone. So Retry and Edit leave the old exchange on the server beside the new one, and an answer cannot be rated. `Connection` is the address and the key alone, and `Connection.parse` refuses a key with a character outside printable ASCII (`[\x21-\x7e]`), since an HTTP header refuses it and the refusal's text would quote the header, key included. On a multi-user server the key opens every user's workspaces and chats: whom the device's chats are saved as is chosen on the Connection page (below), is not a sign-in, and the server takes the `userId` the app sends without checking it.

**Connecting.** With nothing saved, Settings' Connection page (`ConnectionPage`, `ui/settings/connection_page.dart`) opens on the first run's welcome (`Headline`, `ui/widgets/headline.dart`: Connect to your AnythingLLM., the name in the accent), then Scan QR code first where there is a scanner, an or enter a key line (`_OrDivider`), the address and the developer key, each named small over its field (`NamedControl(quiet:)`), where to find a key (a link, Where do I find a key?, which opens How connecting works on its key screen: `showGuide(Guide.connect, step: 1)`), and Connect, which saves them through `SettingsController.connect` once `verify` passes. The key is a `SecretField` (`ui/widgets/fields.dart`): hidden until Show, which reads Hide after and is heard with the field's name, as Edit connection's key is. With the keyboard up (`KeyboardUp`, `ui/widgets/keyboard_up.dart`, which the shell provides since it takes the inset out of the media below it) Connect and the line above it leave the page for a bar of their own over the keyboard, with a `line` rule over it, the page scrolls so the field in use sits just under the top fade (to its end when none has focus) until the person scrolls it, and the help link waits. The line for why a try failed takes room only while it has something to say. That opens How connecting works over the window while `ShellController.guide` is `Guide.connect` (an `OverlayWhile`, which brings the one opened last over the others, so it lies over the camera when `ScanView` opened it): a `Walkthrough` (`ui/settings/walkthrough.dart`) of `connectSteps`, three screens (the two things to bring, where the key comes from, and the address with the https rule). A `Walkthrough` is a pager of `GuideStep`s, swiped or stepped with the arrow keys; a figure is a `GuideFigure` (`ui/settings/guide_figures.dart`). Its last button scans a code where there is a scanner and otherwise closes it. A pairing code carries the address and a key; it is drawn by another AnywhereLLM. Anything else a code names, such as the `&toolkit=...` an older code carried for a server beside AnythingLLM, is ignored, so such a code still pairs. Once a server is saved, the page holds a card of two `InfoRow`s (`ui/settings/rows.dart`): AnythingLLM server, with a Saved tag (`BadgeKind.plain`, no status colour, since it says nothing of whether the server answers) that reads Connected, with the success icon, once Test connection has passed on this page, over the address in mono (left out while Edit connection is open), and Developer key, where it is kept; under it, while Edit connection has it open, the address and key fields with Save key and Scan QR code, and the camera whenever the shell is `scanning`; then, one under another, Test connection (`SettingsController.testSaved`, which verifies the saved connection), Edit connection (Cancel while editing) and Forget this server, which asks `Forget <host>?` in a sheet (`Popup.forgetServer`, a `SheetQuestion`) before it forgets. Another page, a new connection or a failed test puts back Saved. On a server with several users (`SystemController.multiUser`, read by `wantUsers` as the page opens) the card has a third row, Chats saved as, with whom (`PrefsController.chosenUser`, kept in `Prefs.users` by the server's address, or No one chosen yet), which opens Who uses this app?, and under the card a warning, This server has several users: the key opens every chat, whoever it is saved as. Who uses this app? (`WhoUsesSheet`, `ui/settings/who_uses.dart`, `Popup.whoUses`) lists the server's users (`SystemController.users`), each over their role, the one picked in semibold with a check at its end; Done is off until someone is picked, keeps them (`PrefsController.chooseUser`) and reads the workspaces again when that changed who; Close keeps the choice as it was. It opens by itself once after connecting (Connect, Save key or a pairing code: `SystemController.askWhoUses`, taken once by `takeWhoUses`) to a server with several users while no one is chosen there. The address field is a URL field with the `url` autofill hint, and keeps suggestions on: Flutter on Android marks a field without suggestions as a visible password, which replaced the URL keyboard and invited a saved login; `AppField` leaves every other field out of autofill (null `autofillHints`), so the key is never offered a saved login, and a `private` field (the key's) turns off the keyboard's learning.

**Read aloud.** Each finished answer has Read aloud where there is `AppScope.readAloud`. `Speaker` (`ui/chat/speaker.dart`) is the port: `speak` resolves when the reading ends, finished or stopped, and throws when the device cannot speak. `ReadAloud`, in the same file, holds the one answer being read; it reads `splitReasoning`'s answer as `plainText` (`core/markdown.dart`: Markdown parsed, each block a line, a block of text alone one line), and stops when its answer leaves `ChatController.turns`, as when another chat, workspace or server shows. With `ChatSwitch.readAnswers` on, it reads each answer that ran to its end as it finishes, once, while that chat is on screen, when it has an answer beside its reasoning that is not a `modelFailure`: `ChatController.finished` is the last answer that was neither stopped nor failed, and `ReadAloud` takes the `PrefsController` to read the switch. `DeviceSpeaker` (`ui/chat/device_speaker.dart`, `flutter_tts`) is imported by `main.dart` only. It reads in pieces of at most 3500 characters (`speechParts`), since Android's engine refuses more than about 4000 at once. The manifest's `queries` lists `android.intent.action.TTS_SERVICE`. The web UI's server-side speech takes its login, not the developer key.

**Sharing into the app.** AnywhereLLM is a target of the system's share sheet: the manifest's `SEND` filters (`text/*`, `*/*`) and `launchMode="singleTask"`, so a share reaches the app already running. `androidShares` (`ui/share/android_shares.dart`, imported by `main.dart` only, which reads it once as a broadcast stream) gives each share as a `SharedItem`, as `Shares` (`android/.../Shares.kt`) hands it over the `anywherellm/shares` channel (`launchShare` for the one that started the activity, `share` for each later one): a shared file is a `content:` address read through the `ContentResolver` only when it is used (`read`), never written to a file, so the name the sharing app gives is only shown, after `plainFileName`; `Shares` refuses a `file:` path, a file the app's own providers serve, and a `content:` address whose authority holds user info, and ignores an intent the system replays from the recent apps (`FLAG_ACTIVITY_LAUNCHED_FROM_HISTORY`), as `MainActivity` does a notification tap; what it hands over is (`ui/share/shared_item.dart`) a `SharedContent`, which is a `SharedLink` (`sharedTextItem` reads an address alone, or a title over one, as a link), `SharedText` or a `SharedFile` read only when used, or a `SharedPairing` (below). `AppScope.shares` hands each to `ShellController.showShared`, and the shell draws a `SharedContent` in `ShareSheet` (`ui/share/share_sheet.dart`) over everything but a popup: Share to AnywhereLLM Lite: the item, the workspaces with the open one first and chosen, then Add to documents (`addLink`, `addText` or `upload`, then Documents opens) or Ask about it: a new chat in that workspace with the link or the quoted text in the message, or the file attached (at most 20 MB, held to the bytes read as well as to the size the sharing app claims), put in the composer by `ChatController.putInComposer` for the person to ask; nothing is sent. Both open the chosen workspace first, and a sheet put away while a file is read opens nothing. With no server saved it says to connect first.

**Pairing links.** A tapped `anywherellm://connect?...` link opens the app: the manifest's `VIEW` filter (scheme `anywherellm`, host `connect`, `BROWSABLE`) hands it to `Shares`, which gives it as text, and `sharedTextItem` reads a pairing link alone as a `SharedPairing`, as it does one shared as text. The shell draws it in `PairingSheet` (`ui/settings/pairing_sheet.dart`) in `ShareSheet`'s place, since a link can come from any page or message: Connect to this server?, the server, which saved server it replaces, then Cancel and Connect. Connect and a refused link work as they do for a scanned code (`ShellController.pairWith`, taken once by `takePairing`). The sheet shows each address whole, as every mono `InfoRow` does, on as many lines as it takes. Any other `anywherellm:` link is read as a pairing, which says why it cannot be used. A link whose query is not valid UTF-8 is refused as not a pairing code (`parsePairingCode`). The manifest sets `flutter_deeplinking_enabled` to false, so Flutter never pushes the link to the Navigator as a route name.

**Notifications.** The app posts two kinds of Android notification itself, with no UnifiedPush and no server pushing to it: `Answering in <workspace>`, the ongoing one of `AnswerService`, and a ready answer's, drawn by `Notes.kt` (`android/.../Notes.kt`, `ic_notification`, the icon's one-colour vector) on their own channels, Answering and Answers ready, so Android's settings can quiet each. `Notes.retire` deletes the channels an older version made (`anythingllm`, `apps`, `approvals`). There is no Notifications page in Settings. `MainActivity` asks Android for `POST_NOTIFICATIONS` once per run of the activity, when an answer first holds the app with the permission missing, and a notification the person refuses is dropped by Android. A tap on a ready answer's notification opens `MainActivity` with the chat's slug and thread (Main chat's `mainChatOf`), which it hands over the `anywherellm/background` channel (`launchTap` for the one that started the activity, `tap` for one while it runs) as `{slug, thread}`; `AndroidBackground` puts it in `BackgroundWork.taps` as a `ChatTarget` (`ui/chat/background_work.dart`), and `KeepAnswering` opens that chat (`ChatController.openTapped`), once the workspaces are read when the tap started the app, in place of `Prefs.lastChat`.

**Answers out of sight.** When the phone drops the stream, AnythingLLM (1.16.2) runs an agent answer, `automatic` mode's, to its end and saves it, since nothing on the server listens for the disconnect; a chat or query answer it stops (`abortConnectorOnClientDisconnect`) and saves what was written. `ChatController` therefore waits for a `CutOff` answer as above. `KeepAnswering` (`ui/chat/background_work.dart`, built in `main.dart` over the `BackgroundWork`, `ChatController` and `ShellController`) holds the app while `ChatController.working` (an answer runs or is waited for) through the `BackgroundWork` port: `AndroidBackground` (`ui/chat/android_background.dart`, imported by `main.dart` only) over `MainActivity`'s `anywherellm/background` channel, `hold` starting `AnswerService`, a `dataSync` foreground service whose ongoing notification says `Answering in <workspace>` (`Notes.ongoing`, a quiet `answering` channel), so Android neither ends the app nor cuts its connection out of sight; Android 15 ends it after 6 hours a day. Starting it once the app is out of sight is refused, and the answer goes on while it can. A service started that way must reach `startForeground` before it stops, or Android ends the app, so a release that comes first, as when an answer ends at once, is carried out by `onStartCommand` once it has. An answer finished while the app is out of sight (`AppLifecycleListener`) shows as a notification (`BackgroundWork.ready`, drawn by `Notes.ready`), titled with its chat; coming back to the front reads the waited-for answers at once.

**Adapters:**

- `adapters/anythingllm_client.dart` maps HTTP failures to plain-language `ApiException`s. Its own client connects within `connectTimeout` (10 s), less than the 15 s opening `timeout`, so a server that cannot be reached fails as a `SocketException` (`NotSent` for a question) and a timeout means one that took the request. No message may contain the key: an error the client does not map gets a fixed message with no error text, since a platform error can quote the header the key travels in (`unreachable`, `adapters/unreachable.dart`); tests assert this, and `Connection.toString` omits it. `answerImage` is a bare `GET`, without the key, read whole within `timeout` between chunks, at most `maxImageBytes` (16 MB), of an address on the server's own host only (`loadableImage`); any other is refused unread (`offServerImage`), and a redirect is not followed, since it could lead to one.
- `adapters/anythingllm_stream.dart` turns a `stream-chat` response (server-sent `data:` lines) into `TextChunk`s, `StatusChunk`s, `WholeAnswer`s and one closing `ChatDone`; `chatEventsOf` reads the chunks once decoded. An `error` chunk fails the stream. Cancelling the subscription is how Stop ends an answer: `_events` reads the response itself rather than through `chatEvents`' `async*` readers, so the connection closes at once, even before the first chunk, and AnythingLLM stops answering; a tool already running may still finish on the server. An answer or a reset that sends nothing for `idle` (5 minutes) is let go of, since AnywhereLLM sends no pings; that and a dropped connection, once the answer's headers came, are a `CutOff`.
- `adapters/keyring_settings_store.dart` stores the address and the key as one JSON keyring entry; an entry an older version saved with a password, or with the companions' addresses master keeps, is read without them and written again without them.
- `adapters/json_prefs_store.dart` stores `Prefs` in the `File` it is given, `prefs.json` in `path_provider`'s application support directory, written to a temp file and renamed; a save made while another writes waits for it, and only the newest of the saves made meanwhile is written, since each holds everything.

**AnythingLLM API facts the client relies on:**

- `GET /v1/workspaces` gives each workspace's threads with their names but no documents. `GET /v1/workspace/{slug}` gives documents, and threads without names, as a one-item `workspace` array. Thread names therefore come from the list call; document counts cost one call per workspace.
- `DELETE /v1/workspace/{slug}` answers with no JSON, so it decodes with `emptyOk`, which accepts an empty body or a bare `OK`. It deletes the workspace's chats but leaves its documents in the library.
- Renaming a workspace is `workspace/{slug}/update` with `name`. `renameWorkspace` returns the workspace the server answers, and `ChatController` reads the workspaces again if its slug changed. AnythingLLM 1.16.2 keeps the slug.
- A chat is a thread: `thread/new`, `thread/{t}/update`, `DELETE thread/{t}` (empty body), `thread/{t}/chats` for history, `thread/{t}/stream-chat` for answers. The final stream chunk has `close: true` and the `sources` (the client does not read `close`: it ends at `finalizeResponseStream` or the end of the stream); a citation is matched to a file by its `title`. A source whose `chunkSource` is `link://https://...` is a web page an agent read; `citationsOf` keeps that address as the `Citation`'s `url`. A document added with `document/upload-link` has one too (`link://<url>`), so its citations carry its address; any other document's source has none.
- A workspace's Main chat is its chats in no thread, the chat AnythingLLM's web page opens first: `GET workspace/{slug}/chats` for history and `workspace/{slug}/stream-chat` for answers and its reset, which `AnythingLlmApi` takes as a null thread. Neither is sent a `sessionId`, so what the app asks there shows on the web page too, and the other way round. That history call reads 100 (chat messages, the spec says) unless given a `limit`, and oldest first unless given `orderBy=desc`, so `history` asks for the newest `mainChatExchanges` (10000) newest first and puts them oldest first, an exchange at a time (one that already came oldest first, by its ids, is kept as it came). The spec says it lists those chats whatever user sent them. Its `stream-chat` is sent what a thread's is, with no `mode`; that it then answers in the workspace's own chat mode, as a thread's was seen to, is not checked live. Its reset marks the workspace's rows whose `thread_id` and `api_session_id` are both null, by the rule `docs/notes/reset-command-findings.md` read in the server's handler.
- `stream-chat` is sent without `mode`, so a message answers in the workspace's own `chatMode`: `automatic` (Agent: tools when needed), `chat` or `query` (documents only), as in the web UI. A `mode` in the body overrides it, and the app sends one only for a message that carries a document while the workspace is `automatic` (`modeForFiles`, `core/chat.dart`, with the mode `SourcesController.chatMode` holds, which the composer passes to `ChatController.send`): `chat`, since AnythingLLM 1.16.2 reads a document attachment in only outside an agent run, and its agent sends every attachment to the model as an image (`formatMessageWithAttachments`), so a model shown an HTML page or a PDF that way sees nothing or fails. That message answers without tools. `@agent` in a message runs the agent whatever the mode.
- An agent answer streams `agentThought` chunks (`thought`, such as `@agent: Using SearXNG to search for ...`, or, when the provider is verbose, `` @agent is executing `web-browsing` tool {...} ``, read by `toolCall` as `Running web-browsing`) and `textResponseChunk` pieces that include what it wrote before and between tools. It then sends the whole answer as one `textResponse` chunk with `close: true`, and after it a `finalizeResponseStream` chunk with the `sources`: web results, dozens of them. A chat or query answer has its `sources` on the closing `textResponseChunk`, and its `finalizeResponseStream` has no text. Headers come at once, so the opening `timeout` holds even though the first text takes about 9 s. A query refusal is not stored in the history.
- There is no per-document switch. Switching a file on or off is `update-embeddings` with `adds` or `deletes`; the file stays in the library either way, and Documents lists the library (below). An upload is `document/upload`, or `document/upload/{folder}` into a folder named (which the server makes when it has none of that name), then `update-embeddings` with `adds` of each document's `folder/name` path (the folder of the returned `location` and the returned `name`). A web page is `document/upload-link` with `link`, and pasted text is `document/raw-text` with `textContent` and `metadata.title`; both answer `documents` as an upload does and are embedded the same way. Their `addToWorkspaces` field is never sent.
- All three take `metadata` with any of `title`, `docAuthor`, `description` and `docSource` (`DocMeta.toJson`, in `core/server_models.dart`), sent only when one is filled in, except for pasted text, which always sends its `title`. An upload sends it as a multipart field holding the JSON, which AnythingLLM 1.16.2 reads. Pasted text keeps its author, description and source, but the server stores its title as a file name, so `Meeting notes` comes back as `meeting-notes.txt`. There is no `/v1` call that changes details later.
- `stream-chat` takes `attachments` for one message: each is `name`, `mime` and `contentString`, a base64 data URL. `mime` is `image/*` for a picture and `application/anythingllm-document` for any other file, which the server's collector reads in for that message, outside an agent run, and puts in the context; the data URL carries the file's own type for `.pdf`, `.txt`, `.md`, `.csv`, `.html`, `.json`, `.docx`, `.xlsx` and `.pptx`, else `application/octet-stream`. A file the collector cannot read is dropped with a line in the server's log, and the message goes without it. A history entry lists `attachments` for images, with the `contentString` it was sent with, but not for documents. `ChatMessage.attachments` keeps each as a `SentFile` (`core/server_models.dart`): its name and, for a picture, the data URL, decoded only the first time `picture` is read, so reading a history for its ids costs no decoding. A sent `Turn` keeps the picture's bytes the same way, and the question shows it small.
- The server's slash commands are not used. `stream-chat` swaps each server preset for its prompt itself, so one typed is sent as typed, and `/reset` sent as text reaches the model, since the `/v1` handler never checks the built-in commands. The preset list (`GET /api/system/slash-command-presets`, which takes the web login) is left alone. The app's own `/reset` clears a chat with `stream-chat` and `{"reset": true}` and no message (`AnythingLlmApi.resetChat`), which marks that chat's exchanges (a thread's, or Main chat's, those in no thread) `include: false` and answers one `Chat history was reset!` chunk: the model no longer sees them and the history call no longer lists them, here or in the web UI. The server keeps the rows and no call brings them back.
- Developer keys (`/api/system/api-keys`, `/api/system/generate-api-key`) take the web login, so the app does not use them.
- Exchanges: a `/v1` history entry (`convertToChatHistory`) carries `chatId` on both the question and the answer; the closing `finalizeResponseStream` of a chat or query answer carries the new `chatId`, and an agent answer's closing chunk has none (AnythingLLM's `apiChatHandler.js`). Deleting a thread's exchanges (`delete-edited-chats`) and marking an answer (`chat-feedback`) take the web login, so the app does neither.
- `POST /v1/workspace/{slug}/vector-search` with `query` answers `results`, each a passage `text`, a `score` from 0 to 1 and `metadata.title`; with no `topN` or `scoreThreshold` it uses the workspace's own, as an answer does. An empty query is a 400.
- `"Unknown"` is a server placeholder, read as absent. An upload can answer HTTP 200 with `success: false`; `_decode` fails any answer with `success: false`, whatever its status.
- `GET /v1/workspace/{slug}` also carries `openAiPrompt` and the settings columns in `workspaceSettingSpecs` (type and bounds), and each document's `pinned`, which is Read in full. `POST workspace/{slug}/update` takes any of those columns and answers `workspace: null` with a `message` when it refuses.
- A document's `folder/name.json` path is what workspaces use. Stock `GET /v1/document/{name}` leaves out `pageContent`, and no developer-API call gives a document's text, so the app shows none and has no text page.
- The library: `GET /v1/documents` gives `localFiles`, a `documents` folder whose `items` are the folders, each with its `items`, the files: `name` (the stored file) and the document's own JSON less its text (`title`, `wordCount`, `chunkSource`, `url`, `published`, ...). `custom-documents` comes first. A folder listed without its `items` is read with `documents/folder/{name}` (`documents`), which the public spec offers for a server that pages the list; 1.16.2 lists them all (`HttpAnythingLlmApi.libraryFolders`, `libraryFoldersOf`). `published` is the server clock's `toLocaleString`, as `1/16/2024, 3:07:00 PM`, which `addedText` reads (`core/sources.dart`). `url` is `file://<the file read in>` for an upload. `document/create-folder` with `name` makes a folder and answers a 500 with `Folder by that name already exists` for one there. `document/move-files` with `files` of `{from, to}` paths moves documents, but leaves each one any workspace uses where it is and still answers `success: true`, with a `message` (`1/1 files not moved. Unembed them from all workspaces.`), which `moveDocuments` fails as `notMoved`. `DELETE /v1/system/remove-documents` with `names` (paths) deletes documents from the server and from every workspace. `workspace/{slug}/update-pin` with `docPath` and `pinStatus` pins a document the workspace uses, so every answer reads it whole; any other is a bare 404. A folder could be deleted with `document/remove-folder`, which deletes its documents too, so the app never does. `upload-link` and `raw-text` take no folder: their documents land in `custom-documents`.
- `GET /v1/system` gives `settings` with secrets replaced by booleans; a real on-off setting such as `AgentSkillRerankerEnabled` is a boolean too, so the app cannot tell the two apart by value: `settingText` reads any boolean as no text, and an on-off setting is read by its own key. `POST /v1/system/update-env` writes the `.env` from `KEY_MAPPING`'s names. It drops an unknown key or an all-asterisk value without a word, stops at the first failed check with the keys before it already written, and answers `newValues` and `error` with HTTP 200, so `updateSystem` fails on an `error` or on any key sent that is not in `newValues`. `GET /v1/system/vector-count` counts the whole server.
- The closing chunk of an answer, and each history entry, carry `metrics` (`completion_tokens`, `duration`, `outputTps`, `model`, and `inputCost` and `outputCost` when priced; `{}` when unmeasured) and, for an agent, `outputs`: each `{type, payload: {filename, storageFilename, fileSize}}`, `imageGenerationCard` for an image and `PdfFileDownload` and the like for a file. `GET /v1/document/generated-files/{storageFilename}` answers the bytes, an HTML file as `text/html` with `Content-Disposition: attachment`, which `_file` takes where it would refuse the web UI's own page; `generatedFilesOf` keeps only a storage name of letters, digits, `_`, `.` and `-`, and not dots alone.
- Several users: `GET /v1/admin/is-multi-user-mode` answers `isMultiUser`, a single-user server too. `GET /v1/users` lists `{id, username, role}` (`admin`, `manager` or `default`) and answers 401 on a single-user server. `GET /v1/admin/workspaces/{id}/users` takes the workspace's number (`Workspace.id`, from the list call), not its slug, and lists `{userId, role}`; a member with no id is matched by its `username`. An admin and a manager open every workspace whoever it lists, so the app asks only for a default user: `ChatController.load` keeps the workspaces they open (`_openTo`), with no call and no wait for anyone else, and keeps one whose users cannot be read, since the key opens them all anyway. `thread/new` and the thread's `stream-chat` take `userId`, which the app sends for the chosen user, never with `reset`, so Clear chat clears every exchange of the chat; nothing checks it. The workspace's own `stream-chat` takes no `userId`. `workspace/new` lists no users in the workspace it makes, so a default user does not see one they make once the workspaces are read again.
- `GET /v1/system/export-chats?type=csv` answers every chat on the server, every user's, as `text/csv`, read with `_file`.

## Conventions

- Dependencies in `pubspec.yaml` are pinned by series (`">=1.6.0 <1.7.0"`). Moving to a newer series is a deliberate edit.
- Doc comments state what a thing is or does, in plain sentences, with `[name]` references. Match that density in new code.
- Every file that is a source of truth for an app or service (its log, `app.json`, its reducer, a playbook) can be viewed raw in the app. Secrets are the exception: the app names them and never shows their value.
- Cache files are never shown. A value derived from them may be, labelled as derived, as long as it can be rebuilt from files the app shows.
