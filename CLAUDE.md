# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

AnywhereLLM is a Flutter chat client for Linux desktop and Android for an AnythingLLM server. It shows workspaces and their chats (AnythingLLM threads), streams answers, and manages each workspace's files in a Sources panel. Its Files pane shows the server's data as one folder tree. It keeps the server address and API key in the system keyring and its other preferences in a JSON file. It calls AnythingLLM's developer API directly; there is no backend of its own.

## Commands

```bash
flutter pub get
flutter run -d linux
flutter analyze
flutter test                                   # whole suite; fakes the server and the keyring
flutter test test/ui/shell_test.dart           # one file
flutter test --plain-name 'a new server starts afresh'   # one test by name
flutter build linux --debug                    # -> build/linux/x64/debug/bundle/anywherellm
flutter run -d <android-device>                # a phone over adb, or an emulator
flutter build apk --debug                      # -> build/app/outputs/flutter-apk/app-debug.apk
```

The Linux build needs `libsecret-1-dev`. Saving a key at run time needs a running, unlocked secret service such as gnome-keyring.

The Android build is a debug APK only, with no release signing. It needs the Android SDK; `minSdk` is Flutter's default (24), which is what `flutter_secure_storage` requires. On Android the key lives in the Android Keystore.

## Naming

- The product is **AnywhereLLM**: window title, wordmark, binary `anywherellm`, application ID `local.anywherellm.anywherellm` on Linux and Android (`applicationId` and `namespace` in `android/app/build.gradle.kts`). The Dart package is `anywherellm`, so imports are `package:anywherellm/...`. The repository folder is still `everything`.
- `flutter_secure_storage` keys its keyring entry by the application ID (`<APPLICATION_ID>.secureStorage`). Changing `APPLICATION_ID` in `linux/CMakeLists.txt`, or `applicationId` on Android, orphans any saved key.

## Architecture

Imports run `ui -> core <- adapters`. `lib/main.dart` is the only file that knows both sides. `test/layers_test.dart` enforces this with substring checks on import targets:

| Layer | May not import |
| --- | --- |
| `lib/core` | Flutter, `dart:io`, `dart:ui`, `http`, `flutter_secure_storage`, `file_selector`, `desktop_drop`, `ui`, `adapters` |
| `lib/adapters` | Flutter, `dart:ui`, `file_selector`, `desktop_drop`, `ui` |
| `lib/ui` | `dart:io`, `http`, `flutter_secure_storage`, `adapters` |

**Core** holds the ports (`core/ports.dart`: `AnythingLlmApi`, `SettingsStore`, `PrefsStore`), the server models (`core/server_models.dart`: `Workspace`, `Thread`, `ChatMessage`, `WorkspaceDoc`, `DocEntry`), and the pure logic: `core/chat.dart` (`ChatEvent`, `ChatMode`, `defaultTitle`, `Attachment`, `attachmentMime`), `core/files.dart` (`buildTree`, `FileNode`, `NodeBadge`, `chatMarkdown`, `parseSettings`, `modelsText`), `core/sources.dart` (`mergeSources`), `core/prefs.dart` (`Prefs`, `OffDoc`) and `core/upload.dart` (`sendEach`, `linkProblem`) and `core/commands.dart` (`SlashCommand`, `withBuiltIns`, `commandsFor`, `expandPresets`, `resetsChat`). Every failure is an `ApiException(message, {status})`. `NotConfigured` is the subtype thrown when no server is set up. To run calls at once, use `Future.wait` on futures that catch their own errors: the record `.wait` wraps errors in `ParallelWaitError`, which breaks the `on ApiException` handlers.

**The connection** lives in one shared `ConnectionHolder`, built in `main.dart`. `HttpAnythingLlmApi` reads it on every call, so a saved connection takes effect without a restart. `SettingsController` is the only writer, through `load`, `save` and `clear`, which notify listeners. `ChatController` listens and starts afresh when the connection changes; `SessionHost` builds it before reading the keyring, so reading a saved connection is what loads the workspaces. `verify(Connection)` takes an explicit connection so Settings can test one before saving; `SettingsController.connect` verifies first and saves only on success.

**https only on Android.** Dart's `HttpClient` ignores Android's cleartext policy, so the client enforces it itself. `main.dart` builds `HttpAnythingLlmApi` with `allowHttp: !Platform.isAndroid`. When it is false, every call and `verify` fail on an `http://` address before the key is sent, so `connect` never saves one. `SettingsController.allowHttp` gets the same value, so Settings shows an https example address on Android.

**Adapters:**

- `adapters/anythingllm_client.dart` maps HTTP failures to plain-language `ApiException`s. No message may contain the key; a test asserts this, and `Connection.toString` omits it.
- `adapters/anythingllm_stream.dart` turns a `stream-chat` response (server-sent `data:` lines) into `TextChunk`s, `StatusChunk`s, `WholeAnswer`s and one closing `ChatDone`. An `error` chunk fails the stream. Cancelling the subscription is how Stop ends an answer; a tool already running may still finish on the server.
- `adapters/keyring_settings_store.dart` stores the address and key as one JSON keyring entry.
- `adapters/json_prefs_store.dart` stores `Prefs` in `$XDG_CONFIG_HOME/anywherellm/prefs.json` (default `~/.config`), written to a temp file and renamed. On Android, `main.dart` passes `prefs.json` in `path_provider`'s application support directory.

**AnythingLLM API facts the client relies on:**

- `GET /v1/workspaces` gives each workspace's threads with their names but no documents. `GET /v1/workspace/{slug}` gives documents, and threads without names, as a one-item `workspace` array. Thread names therefore come from the list call; document counts cost one call per workspace.
- `DELETE /v1/workspace/{slug}` answers with no JSON, so it decodes with `emptyOk`, which accepts an empty body or a bare `OK`. It deletes the workspace's chats but leaves its documents in the library.
- Renaming a workspace is `workspace/{slug}/update` with `name`. `renameWorkspace` returns the workspace the server answers, and `ChatController` reads the workspaces again if its slug changed. AnythingLLM 1.16.2 keeps the slug. Deleting a library folder is `DELETE document/remove-folder` with `name`; it deletes the folder's documents and takes them out of every workspace.
- A chat is a thread: `thread/new`, `thread/{t}/update`, `DELETE thread/{t}` (empty body), `thread/{t}/chats` for history, `thread/{t}/stream-chat` for answers. The final stream chunk has `close: true` and the `sources`; a citation is matched to a file by its `title`. A source whose `chunkSource` is `link://https://...` is a web page an agent read; `citationsOf` keeps that address as the `Citation`'s `url`. A document's source has no such `chunkSource`.
- `stream-chat` is sent without `mode`, so every message answers in the workspace's own `chatMode`: `automatic` (Agent: tools when needed), `chat` or `query` (documents only), as in the web UI. A `mode` in the body would override it. `@agent` in a message runs the agent whatever the mode. The app writes `chatMode` from the chooser in Sources and from `settings.json`.
- An agent answer streams `agentThought` chunks (`thought`, such as `@agent: Using SearXNG to search for ...`) and `textResponseChunk` pieces that include what it wrote before and between tools. It then sends the whole answer as one `textResponse` chunk with `close: true`, and after it a `finalizeResponseStream` chunk with the `sources`: web results, dozens of them. A chat or query answer has its `sources` on the closing `textResponseChunk`, and its `finalizeResponseStream` has no text. Headers come at once, so the opening `timeout` holds even though the first text takes about 9 s. A query refusal is not stored in the history.
- There is no per-document switch. Switching a file off is `update-embeddings` with `deletes`, and the file is remembered in `Prefs.switchedOff` so Sources keeps listing it. An upload is `document/upload`, then `update-embeddings` with `adds` of each returned `location`. A web page is `document/upload-link` with `link`, and pasted text is `document/raw-text` with `textContent` and `metadata.title`; both answer `documents` as an upload does and are embedded the same way. Their `addToWorkspaces` field is never sent.
- All three take `metadata` with any of `title`, `docAuthor`, `description` and `docSource` (`DocMeta.toJson`, in `core/server_models.dart`), sent only when one is filled in. An upload sends it as a multipart field holding the JSON, which AnythingLLM 1.16.2 reads. Pasted text keeps its author, description and source, but the server stores its title as a file name, so `Meeting notes` comes back as `meeting-notes.txt`. There is no `/v1` call that changes details later.
- `stream-chat` takes `attachments` for one message: each is `name`, `mime` and `contentString`, a base64 data URL. `mime` is `image/*` for a picture and `application/anythingllm-document` for any other file, which the server reads in for that message; the data URL carries the file's own type. A history entry lists `attachments` for images but not for documents; only their names are kept.
- Slash commands: `stream-chat` swaps each preset for its prompt itself, so a preset is sent as typed. `/reset` is not a preset: sent as text it reaches the model. Clearing a chat is `stream-chat` with `{"reset": true}` and no message; it marks the thread's turns `include: false`, which `thread/{t}/chats` then leaves out. A preset whose prompt is `/reset` (such as `/clear`) clears too. The preset list is `GET /api/system/slash-command-presets`, outside `/v1`: it takes the web UI's session, so it answers only while the server has no password, and `slashCommands` fails otherwise.
- `POST /v1/workspace/{slug}/vector-search` with `query` answers `results`, each a passage `text`, a `score` from 0 to 1 and `metadata.title`; with no `topN` or `scoreThreshold` it uses the workspace's own, as an answer does. An empty query is a 400. `GET /v1/system/export-chats?type=` (`jsonl`, `json`, `csv`, `jsonAlpaca`) answers the file itself, not always JSON, so `exportChats` reads the bytes and decodes only a failure. `GET /v1/workspace/{slug}/chats` lists only chats outside any thread and is not used.
- `"Unknown"` is a server placeholder, read as absent. An upload can answer HTTP 200 with `success: false`, and so can `document/create-folder`, `DELETE document/remove-folder`, `document/move-files` and `DELETE system/remove-documents`. `_decode` fails any answer with `success: false`, whatever its status.
- `GET /v1/workspace/{slug}` also carries `openAiPrompt` and the settings columns in `workspaceSettingSpecs` (type, bounds, and whether the app writes it), and each document's `pinned` and `watched`. `POST workspace/{slug}/update` takes any of those columns and answers `workspace: null` with a `message` when it refuses. Pinning is `workspace/{slug}/update-pin` with `docPath` and `pinStatus`.
- `GET /v1/documents` gives the library as `localFiles`: a `documents` folder whose `items` are folders whose `items` are files. A document's `folder/name.json` path is what workspaces, `move-files` and `remove-documents` use. `GET /v1/document/{name}` takes the file name alone and may leave out `pageContent`.
- `GET /v1/system` gives `settings` with secrets replaced by booleans. `modelsText` still keeps only provider, model, engine and vector-database keys, and drops any key naming a key, secret, token or password; a test asserts no secret value survives.
- Nodes outside `/api/v1` (prompt history, memories, jobs, slash commands, skills, the agent's folder) are not in the tree. `.env` and `keys` are shown Locked and never read.

**UI:**

- `ui/app_scope.dart` is an `InheritedWidget` that never notifies. It holds `ShellController` (sidebar drawer, Sources, Settings open, the `Pane`), `SettingsController`, `PrefsController`, `ChatController`, `SourcesController` and `FilesController`. Widgets wrap the controller they read in a `ListenableBuilder`, and `AppScope.of` is safe in `initState`. It also holds `openLink`, a `LinkOpener`: `main.dart` passes `url_launcher`'s `launchUrl`, so `url_launcher` is imported there only, and tests pass a recorder. `ui/links.dart`'s `openLink` opens only what `openableLink` allows (http, https, mailto) and reports anything else, or a link nothing opened, as `ChatController.problem`.
- There are no routes. `ui/shell.dart` lays out `Sidebar | ChatView | SourcesPanel` and draws `SettingsDialog` over them. Below 820 px the sidebar is a drawer; below 1120 px Sources is a drawer. Esc and Back close Settings, then the drawers.
- `ChatController` keeps the workspaces, each workspace's threads, the turns of each opened chat and the one running answer (`_Running`: its turn, its thread, its stream). A `Turn` is itself a `ChangeNotifier`: a streamed chunk notifies only that turn, so only its answer rebuilds. A chat not yet asked anything is a draft held only in the controller; its first message creates the thread, and the first answer renames it with `defaultTitle` unless the person renamed it.
- The sidebar's Chats/Files switch sets `ShellController.pane`. In Files the sidebar holds `FileTree` and the main pane `FilesView`; `ChatView` stays built offstage so a draft and a running answer survive, and Sources is hidden.
- `FilesController` takes the workspaces and threads from `ChatController`. It reads each workspace on its own and the library when Files first shows, and the system settings when `models.json` is opened. It edits a workspace's `PROMPT.md` (an empty prompt is sent as null) and `settings.json` (`chatMode` only as `automatic`, `chat` or `query`), attaches, detaches and pins documents, and uploads, moves and deletes library documents and deletes library folders. It forgets a deleted workspace. It hands each workspace it re-reads to `SourcesController.show` when that workspace is active, and deleting a library document calls `PrefsController.forgetDoc`. Uploads in Sources and Files both go through `ui/widgets/upload_queue.dart`, where a picked or dropped file waits with its own Details (`ui/widgets/doc_details.dart`) until Add, and then through `sendEach` in `core/upload.dart`. The link and pasted-text forms in Sources have Details too. Test a question (`ui/sources/test_question.dart`) shows the passages `SourcesController.search` finds, closest first; tapping one shows it whole and flashes its file. The `/settings` folder in Files has `ExportChats` (`ui/files/export_chats.dart`), which asks where to save before `FilesController.exportChats` fetches the file.
- The active workspace's sidebar row has Rename workspace and Delete workspace. Delete asks first in a `ConfirmBox` (`ui/widgets/confirm_box.dart`), which also asks before a library document or folder is deleted in Files; Esc cancels it. Delete workspace is off while an answer runs in that workspace (`ChatController.answeringIn`), and deleting a workspace forgets its switched-off list.
- `SourcesController` follows `ChatController.activeSlug`, merges the embedded documents with the switched-off ones, and owns the undo toast (6 s) and the citation flash (1.8 s). Files, links (`addLink`) and pasted text (`addText`) all end in `_embedMade`. It reads the workspace's `chatMode`; `ChatModeChooser` (`ui/sources/chat_mode_chooser.dart`) under the Sources heading changes it with `setChatMode`, and waits while an answer runs in that workspace.
- An answer is Markdown, drawn by `ui/chat/answer_body.dart` with `flutter_markdown_plus` and selectable. Code blocks and tables scroll sideways. A finished answer and each code block have a `CopyButton`. Reasoning a model wraps in `<think>` or `<thinking>` is split off by `splitReasoning` in `core/chat.dart`: the chat folds it behind Show reasoning (Thinking... while the block is still open), and Copy and the Files pane's chat Markdown leave it out. Attachments picked in the composer go with the next message only, at most 20 MB each. While an agent answer streams, its latest status line shows under it, and its `WholeAnswer` replaces the pieces streamed so far. Citations past the first five fold behind a count; one that names no file in Sources and has no address shows its title and does nothing when tapped. A link in an answer opens outside the app through `openLink` (`ui/links.dart`), which opens only web and mail links; a refused link, or one nothing on the device opens, shows `ChatController.linkNotice` under the banner for 6 s, apart from `problem`. An image loads only from the connected server's own host, on any port, as a tool's card does (a linked image on another port of the server), and only over https or over the server's own http where http is allowed; any other shows as `[alt: host]`, so an answer cannot make the app fetch an address off that host. A web citation opens its page; a file citation lights up in Sources.
- A message that starts with `/` and has no space yet opens `ui/chat/slash_menu.dart` above it, listing `ChatController.commands` (`/reset`, then the server's presets) that start with what is typed. Up and Down move, Enter or Tab fills the command, Enter on a message that is exactly the command sends it, Esc closes the menu until the message changes. The `/` button starts one in an empty message. `ChatController.send` hands a message that `resetsChat` to `resetChat` and empties the chat on screen; in a draft it only empties the draft.
- `main.dart`'s `SessionHost` awaits the keyring and prefs reads, then loads the chat, or opens Settings when nothing is saved.

## Tests

- `test/support/rig.dart`: `Rig` builds every controller over the fakes; `start()` loads them as the app does.
- `test/support/pump.dart`: `pumpApp(tester, {llm, prefsStore, connection, size, sourcesOpen})` builds the whole shell. `connection` defaults to `sampleConnection`; pass `null` for no server. The harness records every link the app opens in `opened`; `openSucceeds = false` makes opening fail and `openThrows` makes it throw. `tapLink` in `test/ui/links_test.dart` taps a link in a selectable answer at its text's position, found through the `EditableText`'s `renderEditable`.
- `test/support/fake_api.dart`: `FakeAnythingLlm` keeps `FakeWorkspace`s (threads, docs, `prompt`, `settings`), `histories`, a document `library` and empty `folders` in memory, and records calls in `calls` as `name` or `name:arg`. `errors['methodName']` fails a method. `presets` is what `slashCommands` answers; `resetChat` drops the thread's history. `streamChat` answers each of `agentStatus` as a status line, then `answer` and `cited`, or with `hold` set, whatever the test adds to `chat`, and keeps the message's files in `lastAttachments`. `uploadLink` and `uploadText` add a `custom-documents/url-<host>.json` or `raw-<title>.json` document to the library. `searchDocs` finds a passage in each document whose title shares a word with the question, and `exportChats` answers `exported`. Each add keeps its details in `metaOf` by path, and a title among them becomes the document's title. `renameWorkspace` keeps the slug unless `renamedSlug` is set. `removeFolder` drops the folder's documents from the library and every workspace. `planningServer()` is the mockup's data.
- A selectable answer is a read-only `EditableText`; to find a field a person types in, match `EditableText` with `!readOnly`.
- A streaming answer's caret blinks forever, so `pumpAndSettle` times out while one runs; pump a fixed duration instead.
- `test/ui/responsive_test.dart` pumps the chat, the open drawers, Settings, a draft and the no-key banner at 1400, 1000, 780, 500 and 360 px wide, with long unbroken strings, and fails on any overflow. 360x480 is the window's minimum size (`linux/runner/my_application.cc`).

## Conventions

- Dependencies in `pubspec.yaml` are pinned by series (`">=1.6.0 <1.7.0"`). Moving to a newer series is a deliberate edit.
- Doc comments state what a thing is or does, in plain sentences, with `[name]` references. Match that density in new code.
