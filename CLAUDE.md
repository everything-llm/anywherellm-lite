# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

AnywhereLLM is a Flutter chat client for Linux desktop, Android and Chrome for an AnythingLLM server. It shows workspaces and their chats (AnythingLLM threads), streams answers, and manages each workspace's files in a Sources panel. Its Files pane shows the server's data as one folder tree. It keeps the server address and API key in the system keyring and its other preferences in a JSON file. It calls AnythingLLM's developer API directly, or through the everythingllm relay, which keeps an answer going after the app lets go of it; there is no backend of its own.

## Commands

```bash
flutter pub get
flutter run -d linux
flutter analyze
flutter test                                   # whole suite; fakes the server and the keyring
flutter test test/ui/shell_test.dart           # one file
flutter test --plain-name 'a new server starts afresh'   # one test by name
flutter build linux --debug                    # -> build/linux/x64/debug/bundle/anywherellm
flutter run -d <android-device>                # a phone over adb, or an emulator
flutter build apk --debug                      # -> build/app/outputs/flutter-apk/app-debug.apk
flutter build apk --release                    # needs android/key.properties
flutter run -d chrome
flutter build web                              # -> build/web
flutter test tool/store_graphics.dart          # store graphics -> build/store/en-US, or $STORE_GRAPHICS
flutter test tool/app_icon.dart                # icon pictures -> assets/icon
```

The Linux build needs `libsecret-1-dev`. Saving a key at run time needs a running, unlocked secret service such as gnome-keyring.

A release APK is signed with the key named in `android/key.properties` (gitignored), which the personal F-Droid repo's `appstore sync` writes the first time it builds the app. Without that file the release build fails rather than signing with the debug key, because every later update must carry the first release's key. `android.enableResourceOptimizations=false` keeps the launcher icon at the path fdroidserver reads, and `allowBackup` is off so a restored backup never carries a Keystore-encrypted key to a device that cannot decrypt it. Its launcher icon and launch screen are made from `assets/icon` (`icon.png`, `icon-foreground.png` for the adaptive icon, `splash.png`), drawn by `flutter test tool/app_icon.dart` from the robin mark (`RobinMark`, `lib/ui/widgets/robin_mark.dart`, which the logo tile beside the wordmark draws too: the logo study AnywhereLLM Ribbon Trim's angular tail with no spike, in its own units, placed on the 1024 unit box by `_place`) in the design canvas's icon colours, `iconGround` (`#4B5DC3`) and `iconInk` (white), with the `#F2853D` breast. After changing them, run `dart run flutter_launcher_icons` and `dart run flutter_native_splash:create` (configured in `flutter_launcher_icons.yaml` and `flutter_native_splash.yaml`) and commit the generated resources. It needs the Android SDK; `minSdk` is Flutter's default (24), which is what `flutter_secure_storage` requires. On Android the key lives in the Android Keystore.

The F-Droid store page's feature graphic and phone screenshots come from `tool/store_graphics.dart`, which draws them with the app's own fonts over the test fakes, so no real server shows; copy `build/store/en-US` to `metadata/local.anywherellm.anywherellm/en-US` in the app_store project (its `phoneScreenshots` replaced whole, since the store lists every file there, and its `icon.png` kept, since the tool does not draw it), whose `appstore.toml` holds the listing text, and run `appstore sync` there.

## Naming

- The product is **AnywhereLLM**: window title, wordmark, binary `anywherellm`, application ID `local.anywherellm.anywherellm` on Linux and Android (`applicationId` and `namespace` in `android/app/build.gradle.kts`). The Dart package is `anywherellm`, so imports are `package:anywherellm/...`. The repository folder is still `everything`.
- `flutter_secure_storage` keys its keyring entry by the application ID (`<APPLICATION_ID>.secureStorage`). Changing `APPLICATION_ID` in `linux/CMakeLists.txt`, or `applicationId` on Android, orphans any saved key.

## Architecture

Imports run `ui -> core <- adapters`. `lib/main.dart` is the only file that knows both sides. `test/layers_test.dart` enforces this with substring checks on import targets:

| Layer | May not import |
| --- | --- |
| `lib/core` | Flutter, `dart:io`, `dart:ui`, `http`, `flutter_secure_storage`, `file_selector`, `desktop_drop`, `ui`, `adapters` |
| `lib/adapters` | Flutter, `dart:ui`, `file_selector`, `desktop_drop`, `ui` |
| `lib/ui` | `dart:io`, `http`, `flutter_secure_storage`, `adapters` |

**Core** holds the ports (`core/ports.dart`: `AnythingLlmApi`, `SettingsStore`, `PrefsStore`), the server models (`core/server_models.dart`: `Workspace`, `Thread`, `ChatMessage`, `WorkspaceDoc`, `DocEntry`), and the pure logic: `core/chat.dart` (`ChatEvent`, `ChatMode`, `defaultTitle`, `Attachment`, `attachmentMime`, `openableLink`, `loadableImage`, `agentStatus`, `toolCall`, `isAppCard`, `AppCard`, `appCardOf`), `core/files.dart` (`buildTree`, `FileNode`, `NodeBadge`, `FilesSection`, `chatMarkdown`, `parseSettings`), `core/outputs.dart` (`GeneratedFile`, `generatedFilesOf`, `AnswerMetrics` with its `text` and `named` parts, `metricsOf`, `sizeText`), `core/system_settings.dart` (`systemKeys`, `systemChoices`, `chatModelKeys`, `resetsVectors`, `readOnlySettings`, `secretName`, `settingText`, `systemFields`, `systemText`, `parseSystemSettings`), `core/providers.dart` (`ProviderField`, named and typed from its key as a `FieldKind`; `Provider`; `ProviderSetting`, a chooser such as `LLMProvider` with each value's own settings, `labelOf` and `choices`, in its providers' order; `chatModelPrivacy`, `searchModelPrivacy` and `storagePrivacy`, the lines Privacy and data shows; and the choosers `chatProviders`, `embedderProviders`, `vectorProviders`, `imageProviders`, `speechToTextProviders`, `textToSpeechProviders` and `transcriptionProviders`, all in `providerSettings`), `core/chat_log.dart` (`LoggedChat`, `ChatLog`, `sentText`), `core/embeds.dart` (`Embed`, `EmbedMode`, `NewEmbed`, `EmbedChat`, `embedSnippet`), `core/sources.dart` (`SourceFile`, `mergeSources`, `suggestionsFor`), `core/prefs.dart` (`Prefs`, `OffDoc`, `ThemePref`, `TextSize`, `ChatSwitch`) and `core/find.dart` (`matchesSearch`) and `core/markdown.dart` (`answerMarkdown`, `parseAnswer`, `linkedImagesIn`, `mathSyntaxes`, `plainText`) and `core/browser.dart` (`isBrowserTool`, `browserStep`, `BrowserCard`, `browserCards`, `isBrowserPage`) and `core/created.dart` (`CreatedFile`, `CreatedArea`, `CreatedList`, `createdMark`, `createdRoute`) and `core/host_routes.dart` (`cardsPort`, `liveRoute`) and `core/upload.dart` (`sendEach`, `linkProblem`) and `core/connection.dart` (`Connection`, `normalizeBaseUrl`, `isLoopback`, which `chatModelPrivacy` also reads as the server's own machine, with `host.docker.internal` besides, and the pairing code: `pairingCode`, `parsePairingCode`, `pairingProblem`) and `core/commands.dart` (`SlashCommand`, `withBuiltIns`, `commandsFor`, `expandPresets`, `resetsChat`, `whyNoPresets`) and `core/schedule.dart` (`ScheduledJob`, `scheduledJobsOf`, `describeSchedule`, `whenText`) and `core/memory.dart` (`SavedMemory`, `SavedMemories`, `MemorySwitches`, `LongFact`, `LongFile`, `LongMemory`, `RecallHit`, `memoryRoute`, `keptText`, and the limits `globalMemoryLimit`, `workspaceMemoryLimit` and `memoryTextMax`). Every failure is an `ApiException(message, {status})`. `NotConfigured` is the subtype thrown when no server is set up, and `AlreadyAnswering` (`core/errors.dart`, status 409) the one a relay's refused message fails with. To run calls at once, use `Future.wait` on futures that catch their own errors: the record `.wait` wraps errors in `ParallelWaitError`, which breaks the `on ApiException` handlers.

**The connection** lives in one shared `ConnectionHolder`, built in `main.dart`. `HttpAnythingLlmApi` reads it on every call, so a saved connection takes effect without a restart. `SettingsController` is the only writer, through `load`, `save` and `clear`, which notify listeners. `ChatController` listens and starts afresh when the connection changes; `SessionHost` builds it before reading the keyring, so reading a saved connection is what loads the workspaces. `verify(Connection)` takes an explicit connection so Settings can test one before saving; `SettingsController.connect` verifies first and saves only on success.

**Pairing a phone.** Connect a phone on Settings' Connection page draws `pairingCode` (`anywherellm://connect?url=...&key=...`) in `PairingCode` (`ui/settings/pairing_code.dart`) with `QrMark` (`ui/widgets/qr_mark.dart`, the `qr` package), dark on white in both themes, with `pairingProblem`'s warning when the address is loopback or http. On Android, Scan QR code replaces the address and key fields with `AppScope.scanner`; `parsePairingCode` reads the code, the fields are filled, and the card saves through `connect` as for a typed key. A scanned key the server refuses shows in the key field, under why. The scanner is `cameraScanner` (`ui/settings/scan_code.dart`, `mobile_scanner`), imported by `main.dart` only and null off Android, so Linux has no Scan button. `mobile_scanner` bundles Google ML Kit (`libbarhopper_v3.so`, not free software) and adds about 17 MB to the release APK; its manifest adds the CAMERA permission with the camera marked optional.

**Dictation.** The composer has a microphone on Android only. `Dictation` (`ui/chat/dictation.dart`) is the port: `start` gives the words heard so far in full each time and calls `onDone` once when listening ends, with the `DictationEnd` that ended it: `stopped` by `stop`, `paused`, or `failed`. `SpeechDictation` (`ui/chat/speech_dictation.dart`, `speech_to_text`, which has no Linux implementation) is imported by `main.dart` only, and `AppScope.dictation` is null elsewhere. What is heard follows the message as it stood when listening began. A change to the message made otherwise, by typing, a suggestion or Edit, ends the go and is kept. Sending ends the go, and words that arrive after it are dropped. `done` ends a go, not `notListening`, which comes before the last words. With `ChatSwitch.sendDictation` on, a go that ended `paused` sends the message when `canSend` (`ui/chat/composer.dart`) allows it, the same check the Send button makes; a go the person stopped or that failed leaves the message in the box. The manifest adds `RECORD_AUDIO` with the microphone marked optional and a `queries` entry for `android.speech.RecognitionService`; recognition runs in the device's own service, which may send the audio to its maker.

**The server password.** The developer key does not open AnythingLLM's web UI's own routes (`validatedRequest`): the slash-command presets, deleting a thread's exchanges and marking an answer. They take the web login: `POST /api/request-token` with `{"password"}` answers `{valid, token}`, a JWT for 30 days that a new password voids, sent as `Authorization: Bearer <token>` in place of the key. `GET /api/setup-complete` answers without a key or a login; its `results.RequiresAuth` and `results.MultiUserMode` are `ServerAuth` (`core/ports.dart`: `none`, `password`, `multiUser`). After a key is saved, and when a saved connection loads, `SettingsController` asks it (`auth`); for `password` Settings' Connection page shows a Server password card under the key (`PasswordCard`, `ui/settings/password_card.dart`), optional, never a lock. When that read failed, as when the server was out of reach at start, the Connection page asks again (`readAuth`) each time it opens. `savePassword` signs in with it first (`signIn`) and saves it only when the server takes it, with the key in the same keyring entry; `forgetPassword` keeps the key, and a key replaced on the same address keeps the password. A multi-user server (user name and password) gets a note, and the app works without the login. `Connection.password` is part of `==`, never printed and never in the pairing code, so each device signs in itself. `HttpAnythingLlmApi` keeps tokens in memory only, by connection (`_tokens`), signs in on the first call that needs one (`_session`), and on a 401 or 403 forgets the token, signs in once more and tries once more. Without a password such a call goes without the key or a token, which a server with no password answers, and a server with one refuses with 401, read as `This needs the server password. Add it in Settings.`; a refused password is `The server did not accept the password.`, with the server's 401 or, when it answers `valid: false`, 403. `ChatController`, `FilesController` and `SystemController` key their server on the address and key alone (`withPassword(null)`), so saving or forgetting a password does not start them afresh; `ChatController` re-reads the presets and `signedIn` follows it.

**Signing in.** The key card on Settings' Connection page (`ConnectionPage`, `ui/settings/connection_page.dart`) asks for the address and the server's password, and `SettingsController.signIn` gets the developer key itself, so a person never makes or pastes one. It asks `serverAuth` first: `password` needs the password (`Enter the server password.`), `none` takes the address alone and keeps no password, and `multiUser` sets `needsKey`, which shows the key field, since the key routes refuse a multi-user server; the form then takes a key, and Use password goes back, as for a mistyped address. Then `issueKey` (`HttpAnythingLlmApi.keyName`, `AnywhereLLM`) lists the server's keys and reuses the one with that name, or makes it, so every device and every sign-in shares one key; `verify` checks it and it is saved with the password as `connect` saves a typed key (`_use`). Deleting the `AnywhereLLM` key in the web UI disconnects every device. Paste a key swaps the password field for the key field, and the QR code still carries the address and the key.

**Read aloud.** Each finished answer has Read aloud on Android only. `Speaker` (`ui/chat/speaker.dart`) is the port: `speak` resolves when the reading ends, finished or stopped, and throws when the device cannot speak. `ReadAloud`, in the same file, holds the one answer being read; it reads `splitReasoning`'s answer as `plainText` (`core/markdown.dart`: Markdown parsed, each block a line, a block of text alone one line), and stops when its answer leaves `ChatController.turns`, as when another chat, workspace or server shows. With `ChatSwitch.readAnswers` on, it reads each answer that ran to its end as it finishes, once, when it has an answer beside its reasoning that is not a `modelFailure`: `ChatController.finished` is the last answer that was neither stopped nor failed, and `ReadAloud` takes the `PrefsController` to read the switch. `DeviceSpeaker` (`ui/chat/device_speaker.dart`, `flutter_tts`, which has no Linux implementation) is imported by `main.dart` only, and `AppScope.readAloud` is null elsewhere. It reads in pieces of at most 3500 characters (`speechParts`), since Android's engine refuses more than about 4000 at once. The manifest's `queries` lists `android.intent.action.TTS_SERVICE`. The web UI's server-side speech takes its login, not the developer key.

**The relay.** The everythingllm relay (`packages/relay` in that repo) may sit beside AnythingLLM at `/everythingllm/` on the same address, AnythingLLM's tailnet https :3001, and takes the same developer key, which it checks with AnythingLLM's `/api/v1/auth`; a refused key is AnythingLLM's own 403. Every other call goes to AnythingLLM as before. It runs an answer to the end and saves it to the chat whatever the app does. `HttpAnythingLlmApi` asks `GET /everythingllm/health` once per connection, without the key: the relay answers JSON with `service` `everythingllm` and `runs` among its `features`, AnythingLLM its web page with a 200, so the body decides. Any answer but a 5xx or a failed request is remembered, until Test connection asks again (`relayFound(again: true)`) or a run's start fails with 404 or a 5xx, which makes the next message ask again. `relayFound` answers from the same check (`_isRelay`); `SettingsController.readRelay` turns it into `relay`, a `RelayState` (`unknown`, `found`, `absent`, `unreachable`), which a new address or a forgotten connection resets to `unknown`. With the relay, `streamChat` posts `POST /everythingllm/v1/runs` with `workspace`, `thread`, a new `clientId` and `body`, the `stream-chat` body as it would send it, and follows `GET /everythingllm/v1/runs/{id}/events`: each `chunk` event is a `stream-chat` chunk as AnythingLLM sent it, read by `chatEventsOf` as a direct answer is, then `done`, `failed` or `cancelled`, read by name whatever their data. A connection that drops, answers a 5xx, or sends nothing for `quiet` (45 s; the relay pings every 15 s), is opened again with `Last-Event-ID` after each of `rejoinDelays`; once they are used up, the answer fails with `AnswerStillRunning` (`core/errors.dart`), which marks the `Turn` `stillRunning`: the chat draws it as a calm `AlertBox` of `AlertKind.info` (`ui/widgets/basics.dart`), Still being written, not as the red The answer stopped, and it stays `unfinished`, so the chat is read again when it opens. While it is the last answer of the chat on screen, `ChatController` checks on it after each of `checkEvery` (10, 20 and 40 s, then every 60 s), when the app shows again, and on the box's Check now (`checkAnswer`): it takes the chat's newest run from `relayRuns`, follows it again (`_rejoin`) while it runs, and shows the chat's history once it holds the answer; a run that failed, was cancelled or is not listed turns the answer into the red The answer stopped, in the relay's `error` when it gave one, with Ask again. A relay that cannot be asked, or a `done` run whose answer the history does not hold yet, leaves it as it is. The box's Stop (`stopLost`) cancels that run with `cancelRun` and marks the answer stopped. A chat that already has a run going is a 409, which `_beginRun` turns into `AlreadyAnswering`, in the relay's words: the answer may have been started on another device. `ChatController._refuse` then takes the question and its empty answer back out of the chat, keeps the message and its files for the composer (`takeForComposer`, which `Composer` reads in `_chatChanged` and puts back while the field and attachments are empty; only in that chat), and follows the run already going through `rejoinChat` (`GET /everythingllm/v1/runs?status=running`, its `/events` from the start) as `_rejoin(elsewhere: true)` does, with no `Kept answering while the app was closed.` line. Meanwhile `alreadyAnswering` holds, and the composer shows the warn notice `This chat is still answering, maybe on another device. Send when it ends, or stop it.` over its card, until that run ends or none is found. Stop cancels it through `stopChat`, and Send when done sends the kept message when it ends. The red The answer stopped box never shows for a 409. Opening a chat also follows a run of it this run of the app did not start (`_rejoin`). Cancelling the subscription lets go of the run and closes the events connection at once, through a `gone` signal, because an `async*` body waiting in `await for` sees a cancel only at its next `yield`. Stop calls `stopChat` first, which posts `/everythingllm/v1/runs/{id}/cancel`, waiting for the id when the relay has not yet answered the start; a new server or the app closing leaves the run going. A chat whose last answer failed or was stopped (`Turn.unfinished`) is read again the next time it is opened, so what the relay saved shows. Clearing a chat goes to AnythingLLM's own `stream-chat`, not through the relay.

**Tool approvals.** AnythingLLM's developer API runs an agent headless and refuses every tool that is not already approved, so an approval reaches the app only through the relay. The relay's health check lists `approvals` among its `features`; `_approvals` keeps that per server beside `_relays`, and only then does the run's start body carry the connection's `password`, for that run alone, since the relay uses the web login and agent websocket for it (a reset, a run without a password and a relay without `approvals` use the developer API as before). The relay's `approval` event reads as an `ApprovalRequest` (`core/chat.dart`: the run, the request id, the tool, its description and arguments, and `expires`, by the relay's clock) and `approval-settled` as an `ApprovalSettled`, both through `_runChunks` as the synthetic chunks `toolApproval` and `toolApprovalSettled`, so `chatEventsOf` stays the one reader. `Turn.approvals` holds the unanswered ones; `ChatController.approve` removes the request at once, sends `answerApproval` (`POST /everythingllm/v1/runs/{id}/approvals/{requestId}` with `{"approved"}`, by the key alone) and puts the request back with a `problem` when the call fails, unless the relay answers 409 (answered on another device, or the server stopped waiting). `ApprovalCard` (`ui/chat/approval_card.dart`) draws it under a streaming answer, Allow and Deny, the arguments on request, and the time left; past `expires` it says the server refused the tool. A rejoined run replays its events, so an unanswered request shows again.

**Answers the relay finished meanwhile.** `relayRuns` (the one reader of the relay's runs, which Activity uses too, below) lists the answers the relay ran in the 7 days it keeps them, each a `RelayRun` (`core/server_models.dart`), less a reset; without a relay it fails with an `ApiException`, which `readFinishedRuns` reads as none. `Prefs.seen` keeps when each chat was last on screen on this device, by server and workspace; `ChatController` writes it as a chat comes on and leaves the screen, in the same write as the last chat (`PrefsController.showChat`), at most `Prefs.seenMax` (50) a workspace, and `noteSeen` when the app hides or exits. `readFinishedRuns`, after a server's first load and when the app shows again (`SessionHost`'s `AppLifecycleListener`), gives the `ReadyDot` to each chat not on screen whose run is `done` and finished after it was last seen; a chat never seen here gets none.

**Sharing into the app.** On Android AnywhereLLM is a target of the system's share sheet: the manifest's `SEND` filters (`text/*`, `*/*`) and `launchMode="singleTask"`, so a share reaches the app already running. `androidShares` (`ui/share/android_shares.dart`, `receive_sharing_intent`, imported by `main.dart` only, which reads it once as a broadcast stream) gives each share as a `SharedItem` (`ui/share/shared_item.dart`): a `SharedLink` (`sharedTextItem` reads an address alone, or a title over one, as a link), `SharedText` or a `SharedFile` read only when used. `AppScope.shares` hands each to `ShellController.showShared`, and the shell draws `ShareSheet` (`ui/share/share_sheet.dart`) over everything but a popup: Share to AnywhereLLM: the item, the workspaces with the open one first and chosen, then Add to documents (`addLink`, `addText` or `upload`, then Documents opens) or Ask about it: a new chat in that workspace with the link or the quoted text in the message, or the file attached (at most 20 MB), put in the composer by `ChatController.putInComposer`, in the same store as a refused message, for the person to ask; nothing is sent. Both open the chosen workspace first. With no server saved it says to connect first. Esc and Back close it before anything else. `receive_sharing_intent` asks for `compileSdk 37`, which the SDK installs as `android-37.0`; `android/build.gradle.kts` builds it against 36.

**Memory.** Settings' Memory page (`SettingsPage.memory`, `MemoryPage`, `ui/settings/memory_page.dart`) sits beside Server under AnythingLLM, on a desktop's list and a phone's, its `parent` null; a phone's workspace page has a Memory row under How it answers, which shows that workspace (`MemoryController.show`) and opens it. `MemoryController` (`ui/state/memory_controller.dart`, built in `main.dart` over the settings, `ChatController` and the API) follows the open workspace until the page's Workspace chooser picks another, and starts afresh on another connection, password included, since the saved memories sign in with it; the page reads it through `want`, as Artifacts does. It shows two memories. AnythingLLM's saved memories, which every chat is shown word for word, at most `globalMemoryLimit` (5) for every workspace and `workspaceMemoryLimit` (20) for each: the Saved memories and Learn from chats switches (`memorySwitches`, `setMemorySwitches`), then while on, the lists `Every workspace · N of 5` and `Only <workspace> · N of 20`, a full one saying so in place of Add a memory. And the everythingllm host's long-term memory, which no chat is shown and the agent recalls by meaning: Find by meaning (`recallMemory`, 400 ms after typing stops, Closest first with each `82% match`), Facts with Remember something, and Files read in, those still being read and those that failed; a server without the route (`longMemory` null) says it has none. A row opens under itself, one at a time: a saved memory's text and Shown in (Every workspace, or `Only <workspace>`) with Delete, Cancel and Save; a fact or a file's text asks before Forget in a `ConfirmBox`, and a fact is not edited, since the host only remembers and forgets. Every change reads both memories again, and a failed one shows over its half, kept through that read. A Remember of what a fact already says shows `Already kept: …`.

**Upcoming.** A phone's drawer has Upcoming (`UpcomingRow`, `ui/upcoming.dart`, at its foot), with how many jobs once `SystemController.readJobs` has read them, which it asks the first time it shows on a server. `scheduledJobs` reads `GET /api/scheduled-jobs` through `_session`, with the server's password as the presets are, into `ScheduledJob`s (`core/schedule.dart`: `name`, `schedule`, a cron in UTC, `nextRunAt`, `lastRunAt`, `enabled`, `latestRun`, and the workspace in any form the server gives it). `UpcomingPage`, a page over the chat (`ShellController.phonePage`, `PhonePage.upcoming`), reads them afresh and lists each, read only, in one card: its name over one line of its workspace, `describeSchedule` (the cron in plain words in local time, or the cron marked UTC) and when it runs next (`whenText`) or Off, or Last run failed in red, then Read only here. and Edit in AnythingLLM's web page. A refused read says why, with Open Connection.

**Activity.** A phone's drawer has Activity above Upcoming (`ActivityRow`, `ui/activity.dart`), with how many answers the relay is writing (`N running`) once `SystemController.readActivity` has read them, which it asks when the drawer first opens on a server and which joins a read already going. `relayRuns` reads `GET /everythingllm/v1/runs` (every run the relay keeps, 7 days) into `RelayRun`s (`core/server_models.dart`: `id`, `workspace`, `thread`, `status`, `question`, `error`, `started`, `finished`, `endedAt`; `running`, `failed`, `done`), less a reset (`question` `/reset`, dropped in `_listRuns`, which `rejoinChat` reads through too); a server with no relay fails with an `ApiException` saying so, which `ActivityPage` shows. `ActivityPage`, a page over the chat (`PhonePage.activity`), reads them afresh when it opens, on its refresh button, and every 10 s while one runs, and lists Running now, then Finished, last 7 days (`activityGroups`, `core/activity.dart`, sorts each newest first once per read), each group in a card: the workspace and chat, the question, and in bold Answering with how long, Done, Failed with the relay's reason on the same line, or Stopped with how long ago (`elapsedText`, `agoText`, `core/activity.dart`). A running row has Stop, `cancelRun` (`POST /everythingllm/v1/runs/{id}/cancel`, by run id, so it stops an answer this device never followed); a done row whose chat has not been opened since (`ChatController.isReady`) has the accent dot. A row opens its chat (`select`), unless the chat is gone.

**The chat's browser.** The everythingllm host tells a client with a developer key the browser of a chat: `GET https://<host>:8445/_live/browser/chat/<workspace>/<thread slug>` (`browserRoute`, `core/browser.dart`, over `liveRoute` and `cardsPort`, `core/host_routes.dart`: the machine's route for `/_live`) answers `{tab, logins}` as JSON, with CORS: the `tab` has `card`, `page` (its take-over view), `frame`, `state` (`working`, `idle`, `waiting`, `user` or `closed`), `title`, `site` (the page's registrable name, never its address, whose path can hold a token) and `last`, and each login request its `card`, `page`, `site` and `state` (`waiting`, `saving`, `saved`, `declined` or `expired`), newest first (`ChatBrowser`, `BrowserTab`, `BrowserLogin`, `core/browser.dart`). `/card.jpg` on the same route is the tab as one JPEG now, with an `ETag` and a 304 for one unchanged, a 404 while the chat has no tab, and reading it counts as watching the tab, which keeps the host's browser from being stopped; it is how a browser build draws the tab, whose own card has no CORS. `POST …/give` hands the browser back to the agent while the person has it and answers as the GET does. `chatBrowser`, `browserFrame` and `handBackBrowser` are the port's calls, and the app reads only `page`, `state`, `title`, `site` and `last` of the tab and `card`, `page` and `state` of a login request; the first reads any failure, a missing route or an unknown chat as null, so a server without the route leaves a chat with what its answers show. A chat that is a draft has none. The key goes only to that route, on the connected server's host.

**The browser on a phone.** Where there is `AppScope.takeover` (a `TakeoverView`; Android: `TakeoverWebView`, `ui/chat/takeover_web_view.dart`, `webview_flutter`, imported by `main.dart` only), `BrowserPanel` on a phone is `BrowserScreen` (`ui/chat/browser_screen.dart`): the tab's take-over view (`BrowserTab.page`, else a card's link) full screen, at `themedPage`, keyed by the chat and kept at the first address it got. **Created files.** The everythingllm host lists a workspace's sandbox files for a client with the developer key, on the same `:8445` `/_live` route as the browser: `GET https://<host>:8445/_live/sandbox/files/<workspace>` answers `{workspace, used, warn, limit, truncated, files}` (`CreatedList`; `used` is the whole workspace's bytes against `limit`, 5 GB, and `warn`, 4 GB), each file `{id, name, dir, size, modified, area, thread?, expires?, url?}` (`CreatedFile`, times in seconds), newest first, at most 2000. `area` is `project` (kept, with browser downloads in `project/downloads`), `work` (a chat's working file, gone at `expires`, a week after the chat last used the sandbox), `public` (on the web, at `url`) or `shared` (other workspaces can read it); an app's own files and hidden entries are left out, and so are deep research reports and AnythingLLM's own files. A file's `id` is the one thing the other calls take, as `?path=<id>`: `GET …/download` (the bytes as an attachment, 64 MB at most, else 413), `POST …/keep` (a working file moved to the same path in `project/`, answering its new `id`; 409 when `project/` has one or a run holds the workspace) and `POST …/delete` (one plain file, 409 while a run holds the workspace); an id that names nothing is a 404 with JSON. `createdFiles`, `downloadCreated`, `keepCreated` and `deleteCreated` are the port's calls, all through `_host` (which the browser's calls use too) with the key and never the password. A 404 that is not JSON, as a host without the route answers, is remembered per connection and kind (`_routeMissing`, `_noRoute`, cleared by Test connection's relay check) and read as null, which `CreatedController` (`ui/state/created_controller.dart`, built over the settings, `ChatController` and the API in `main.dart`) holds as `unavailable`; a JSON 404, `no sandbox for this workspace`, is an empty list; any other failure is the controller's `problem`, shown over the list and cleared by the next read. The controller follows the open workspace and server, reads when the view first asks (`want`, once: a failed read waits for Refresh), and after each Keep or Delete, and keeps a failed change's `problem` through that re-read. `createdMark` says only what differs from a kept file: `Goes in N days` (rounded up, `Goes soon` once past), `On the web`, `Other workspaces can read`; it sits beside the name with the row's actions (Keep, Download, Open page, Delete) where the list is at least 580 px wide, and under it narrower, each row a `SourceRow.label`. `createdMeta` is the line under the name: the size, or `Page` and the address for a page; `downloaded by the browser` for a kept file in `downloads` (`CreatedFile.fromBrowser`), else the folder; and the age. The host names a working file's chat only by AnythingLLM's numeric thread id, which the `/v1` thread list leaves out, so a row cannot say which chat made it. A row's Download goes through `saveFile` and `CreatedController.bytes`, Open page (a `.html` file on the web) through `openLink`, and Delete asks in a `ConfirmBox`. Download all, which the canvas shows, is not built: the host has no call that zips a workspace's files. On a phone the drawer's Artifacts row (`ArtifactsRow`, `ui/artifacts.dart`) counts the open workspace's created files, read through `CreatedController.want` when the drawer opens, and is left out while the controller is `unavailable`; it reads them afresh each time the drawer opens. A row opens `CreatedSheet` (`ShellController.openCreatedSheet`, a `CreatedSheetFor` popup), except a Markdown file's (`CreatedFile.isMarkdown`: `.md` or `.markdown`), which opens `CreatedText` (`ui/created_text.dart`, `ShellController.showCreatedText`) over the page: its name under Back, which gives the list back, Download as the header's action, and the file drawn by `AnswerBody` in a card, read through `CreatedController.bytes` unless it is over `CreatedText.maxBytes` (2 MB); its More is then a button that opens the sheet. The sheet has Read for a Markdown file, Download (`saveCreated`), Open page for a page on the web, Keep for a working file, and Delete file, which asks first in a `SheetQuestion` (`ui/widgets/sheet.dart`, which the chat's and the workspace's delete use too). The same answer's `apps`, from a host that lists them (null otherwise, and the page leaves Apps out), are the workspace's apps as `CreatedApp`s (`core/created.dart`: `id` `apps/<name>`, `title`, `kind`, the starter it was made from, which `about` names as List, Tracker, Timer, Deck or Calendar before the host's `summary`, `modified`, `page`, `card` and `link`, or the `error` its data gave), last changed first; `CreatedFile` and `CreatedApp` are the sealed `Created`, which `CreatedController.remove`, `CreatedSheetFor` and `deleteCreatedQuestion` take. **https only on Android.** Dart's `HttpClient` ignores Android's cleartext policy, so the client enforces it itself. `main.dart` builds `HttpAnythingLlmApi` with `allowHttp: !Platform.isAndroid`. When it is false, every call and `verify` fail on an `http://` address before the key is sent, so `connect` never saves one. `SettingsController.allowHttp` gets the same value, so Settings shows an https example address on Android.

**In a browser.** `main.dart` asks `kIsWeb` before `Platform`, which throws there, and hands the adapters what differs as values: `HttpAnythingLlmApi.browserOrigin` (the page's origin, null elsewhere) and `KeyringSettingsStore.failureHint`. The prefs go to `BrowserPrefsStore` (`adapters/browser_prefs_store.dart`, `package:web` local storage, one `anywherellm.prefs` entry), which uses `dart:js_interop`, which the VM cannot compile, so `main.dart` imports it conditionally over a `_stub` file that throws. Saving a file is `saveAsDownload` (`ui/files/save_file.dart`), `XFile.fromData(...).saveTo`, a download the browser files where its settings say, so nothing is asked first. `flutter_secure_storage` keeps the connection in local storage, encrypted with a key held beside it, and its WebCrypto works only over https or from localhost. A page served over https uses https only (`allowHttp` false), since the browser blocks http from it. Every request is cross-origin: AnythingLLM's `cors` answers any origin, and a failed `fetch` (a server out of reach or one that does not allow the page's origin, which the browser does not tell apart) reads `... A browser also says this when the server does not allow requests from <origin>.` The relay sends no CORS headers, so its health check fails, which `_isRelay` remembers as no relay when `browserOrigin` is set, and answers go straight to `stream-chat`; elsewhere a failed health check fails the message as before. Answer images from another port, such as the everythingllm host's cards on :8445, need that host's CORS too and fail without it. The Android-only features (dictation, Read aloud, Scan QR code) stay off.

**Adapters:**

- `adapters/anythingllm_client.dart` maps HTTP failures to plain-language `ApiException`s. No message may contain the key, the password or a login token; tests assert this, and `Connection.toString` omits them.
- `adapters/image_frames.dart` reads an answer image's response: the boundary from `http_parser`'s `MediaType`, then each part of a `multipart/x-mixed-replace` body to its `Content-Length` until `--boundary--` (a part without one fails), or any other body whole, at most 16 MB an image. It is built on a `StreamController`, not `async*`, so a cancel closes the connection at once rather than at the next frame; `answerImage` likewise lets go of a response whose headers come after a cancel.
- `adapters/anythingllm_stream.dart` turns a `stream-chat` response (server-sent `data:` lines) into `TextChunk`s, `StatusChunk`s, `WholeAnswer`s and one closing `ChatDone`. An `error` chunk fails the stream. Cancelling the subscription is how Stop ends a direct answer: `_events` reads the response itself rather than through `chatEvents`' `async*` readers, so the connection closes at once, even before the first chunk, and AnythingLLM stops answering; a tool already running may still finish on the server. A direct answer or a reset that sends nothing for `idle` (5 minutes) fails, since AnythingLLM sends no pings. `chatEventsOf` reads chunks already decoded, as a relay's run hands them back, and `serverSentEvents` splits a response into `id`, `event` and `data`.
- `adapters/keyring_settings_store.dart` stores the address, the key and the server's password, when one is saved, as one JSON keyring entry; an entry without a password loads with none.
- `adapters/json_prefs_store.dart` stores `Prefs` in `$XDG_CONFIG_HOME/anywherellm/prefs.json` (default `~/.config`), written to a temp file and renamed; a save made while another writes waits for it, and only the newest of the saves made meanwhile is written, since each holds everything. On Android, `main.dart` passes `prefs.json` in `path_provider`'s application support directory.

**AnythingLLM API facts the client relies on:**

- `GET /v1/workspaces` gives each workspace's threads with their names but no documents. `GET /v1/workspace/{slug}` gives documents, and threads without names, as a one-item `workspace` array. Thread names therefore come from the list call; document counts cost one call per workspace.
- `DELETE /v1/workspace/{slug}` answers with no JSON, so it decodes with `emptyOk`, which accepts an empty body or a bare `OK`. It deletes the workspace's chats but leaves its documents in the library.
- Renaming a workspace is `workspace/{slug}/update` with `name`. `renameWorkspace` returns the workspace the server answers, and `ChatController` reads the workspaces again if its slug changed. AnythingLLM 1.16.2 keeps the slug. Deleting a library folder is `DELETE document/remove-folder` with `name`; it deletes the folder's documents and takes them out of every workspace.
- A chat is a thread: `thread/new`, `thread/{t}/update`, `DELETE thread/{t}` (empty body), `thread/{t}/chats` for history, `thread/{t}/stream-chat` for answers. The final stream chunk has `close: true` and the `sources`; a citation is matched to a file by its `title`. A source whose `chunkSource` is `link://https://...` is a web page an agent read; `citationsOf` keeps that address as the `Citation`'s `url`. A document added with `document/upload-link` has one too (`link://<url>`), so its citations carry its address; any other document's source has none.
- `stream-chat` is sent without `mode`, so every message answers in the workspace's own `chatMode`: `automatic` (Agent: tools when needed), `chat` or `query` (documents only), as in the web UI. A `mode` in the body would override it. `@agent` in a message runs the agent whatever the mode. The app writes `chatMode` from the composer's Answer from menu and from a workspace's `settings.json` in Files.
- An agent answer streams `agentThought` chunks (`thought`, such as `@agent: Using SearXNG to search for ...`) and `textResponseChunk` pieces that include what it wrote before and between tools. It then sends the whole answer as one `textResponse` chunk with `close: true`, and after it a `finalizeResponseStream` chunk with the `sources`: web results, dozens of them. A chat or query answer has its `sources` on the closing `textResponseChunk`, and its `finalizeResponseStream` has no text. Headers come at once, so the opening `timeout` holds even though the first text takes about 9 s. A query refusal is not stored in the history.
- There is no per-document switch. Switching a file off is `update-embeddings` with `deletes`, and the file is remembered in `Prefs.switchedOff` so Sources keeps listing it. An upload is `document/upload`, then `update-embeddings` with `adds` of each returned `location`. A web page is `document/upload-link` with `link`, and pasted text is `document/raw-text` with `textContent` and `metadata.title`; both answer `documents` as an upload does and are embedded the same way. Their `addToWorkspaces` field is never sent.
- All three take `metadata` with any of `title`, `docAuthor`, `description` and `docSource` (`DocMeta.toJson`, in `core/server_models.dart`), sent only when one is filled in. An upload sends it as a multipart field holding the JSON, which AnythingLLM 1.16.2 reads. Pasted text keeps its author, description and source, but the server stores its title as a file name, so `Meeting notes` comes back as `meeting-notes.txt`. There is no `/v1` call that changes details later.
- `stream-chat` takes `attachments` for one message: each is `name`, `mime` and `contentString`, a base64 data URL. `mime` is `image/*` for a picture and `application/anythingllm-document` for any other file, which the server reads in for that message; the data URL carries the file's own type. A history entry lists `attachments` for images, with the `contentString` it was sent with, but not for documents. `ChatMessage.attachments` keeps each as a `SentFile` (`core/server_models.dart`): its name and, for a picture, the data URL, decoded only the first time `picture` is read, so reading a history for its ids costs no decoding. A sent `Turn` keeps the picture's bytes the same way, and the question shows it small.
- Slash commands: `stream-chat` swaps each preset for its prompt itself, so a preset is sent as typed. `/reset` is not a preset: sent as text it reaches the model. Clearing a chat is `stream-chat` with `{"reset": true}` and no message; it marks the thread's turns `include: false`, which `thread/{t}/chats` then leaves out. A preset whose prompt is `/reset` (such as `/clear`) clears too. The preset list is `GET /api/system/slash-command-presets`, outside `/v1`: it takes the web login, so `slashCommands` reads it with the server's password, or on a server that has none, and fails with 401 otherwise.
- Developer keys: `GET /api/system/api-keys` answers `apiKeys`, each with `id`, `name` and `secret`, and `POST /api/system/generate-api-key` with `{"name"}` answers `apiKey` and `error`. Both take the web login, or nothing on a server without a password, and answer 401 in multi-user mode, where an admin's are `/api/admin/api-keys` and `/api/admin/generate-api-key`.
- Saved memories: `GET /api/admin/system-preferences-for?labels=memory_enabled,memory_auto_extraction` answers `settings` with each as text (`memory_enabled` off unless `true`, `memory_auto_extraction` on unless `false`), and `POST /api/admin/system-preferences` takes them the same way. While `memory_enabled` is off every memory route answers 403 `Personalization is disabled.`, so `MemoryController` reads the switches first. `GET /api/workspaces/{slug}/memories` answers `memories` with `global` and `workspace`, each memory `id`, `content` and `scope`; `POST` there takes `{content, scope}`, `PUT /api/memories/{id}` `{content}`, `DELETE /api/memories/{id}` deletes, and `POST /api/memories/{id}/promote` or `/demote/{slug}` moves one; each answers `memory`, or 400 with `error` (a full list: `Maximum global memory limit (5) reached.`). All take the web login, through `_session`; the admin routes answer a single-user server.
- The long-term memory: the everythingllm host's `memory-runner` answers `https://<host>:8445/_live/memory/<workspace>` (`memoryRoute`) with the developer key, never the password, and CORS: `{workspace, count, facts, files, waiting, failed}`, the newest 500 facts that workspace's agent sees (global and its own, each `id` `m<number>`, `scope` `global` or `workspace`, `text`, `created`), its files read in (`path`, `parts`, `ingested`), those the ingest queue holds (`parts` still to go) and those it gave up on (`error`); `GET …/recall?q=` answers `hits`, closest first, each a fact or a file's part (`path`, `part`) with its `score` from 0 to 1, and 503 while the model loads; `POST …/remember` takes `{text, scope}` and answers `{fact, new}`, `new` false for a fact one already says; `POST …/forget?id=m12` or `?path=` forgets a fact or a file's text (the file stays). A 404 that is not JSON is remembered as no route, as for the created files (`_noRoute`, kind `memory`).
- Exchanges: a `/v1` history entry (`convertToChatHistory`) carries `chatId` on both the question and the answer, and `feedbackScore` (`true`, `false` or null) on the answer; the closing `finalizeResponseStream` of a chat or query answer carries the new `chatId`, and a relay run hands it back unchanged. An agent answer's closing chunk has none (AnythingLLM's `apiChatHandler.js`), and every answer in `automatic` mode is an agent's, so while `signedIn` `ChatController` reads the chat's history after an answer that ends without one (`_learnIds`). It takes the last entry's id only while the exchange is still the last in its chat, only when that entry asks the same question, and only when the id is newer than every id the chat has, since a wrong id would make Retry or an edit delete other exchanges. `DELETE /api/workspace/{slug}/thread/{t}/delete-edited-chats` with `{"startingId"}` deletes the thread's exchanges from that id on and answers a bare `OK` (`dropFrom`); `POST /api/workspace/{slug}/chat-feedback/{chatId}` with `{"feedback": true|false|null}` marks an answer (`setFeedback`). Both take the web login. `update-chat`, which rewrites one exchange's text, is not used.
- `POST /v1/workspace/{slug}/vector-search` with `query` answers `results`, each a passage `text`, a `score` from 0 to 1 and `metadata.title`; with no `topN` or `scoreThreshold` it uses the workspace's own, as an answer does. An empty query is a 400. `GET /v1/system/export-chats?type=` (`jsonl`, `json`, `csv`, `jsonAlpaca`) answers the file itself, not always JSON, so `exportChats` reads the bytes and decodes only a failure. `GET /v1/workspace/{slug}/chats` lists only chats outside any thread and is not used.
- `POST /v1/admin/workspace-chats` with `{"offset": page}` answers `{chats, hasPages}`: every workspace's chats, 20 a page (`ChatLog.pageSize`), newest first, each with `workspace` (`name`, `slug`), `prompt`, `response` (JSON holding `text`, or the text itself), `createdAt` and `user.username`. It answers on a single-user server, though the other `/v1/admin` routes refuse one. `workspaceChats` reads it into a `ChatLog`.
- `"Unknown"` is a server placeholder, read as absent. An upload can answer HTTP 200 with `success: false`, and so can `document/create-folder`, `DELETE document/remove-folder`, `document/move-files` and `DELETE system/remove-documents`. `_decode` fails any answer with `success: false`, whatever its status.
- `GET /v1/workspace/{slug}` also carries `openAiPrompt` and the settings columns in `workspaceSettingSpecs` (type and bounds), and each document's `pinned` and `watched`. `POST workspace/{slug}/update` takes any of those columns and answers `workspace: null` with a `message` when it refuses. Pinning is `workspace/{slug}/update-pin` with `docPath` and `pinStatus`.
- `GET /v1/documents` gives the library as `localFiles`: a `documents` folder whose `items` are folders whose `items` are files. A document's `folder/name.json` path is what workspaces, `move-files` and `remove-documents` use. `GET /v1/document/{name}` takes the file name alone and may leave out `pageContent`.
- `GET /v1/system` gives `settings` with secrets replaced by booleans; a real on-off setting such as `AgentSkillRerankerEnabled` is a boolean too, so a secret is a boolean whose key names a key, secret, token, password or connection string. `POST /v1/system/update-env` writes the `.env` from `KEY_MAPPING`'s names (`systemKeys`, less `AuthToken` and `JWTSecret`, which need the server's force mode). It drops an unknown key or an all-asterisk value without a word, stops at the first failed check with the keys before it already written, and answers `newValues` and `error` with HTTP 200, so `updateSystem` fails on an `error` or on any key sent that is not in `newValues`. Changing `EmbeddingEngine`, `EmbeddingModelPref` or `AzureOpenAiEmbeddingModelPref` makes the server delete every vector (`handleVectorStoreReset`), and changing `VectorDB` deletes the old database's; the app never writes `VectorDB`. `GET /v1/system/vector-count` counts the whole server.
- The closing chunk of an answer, and each history entry, carry `metrics` (`completion_tokens`, `duration`, `outputTps`, `model`, and `inputCost` and `outputCost` when priced; `{}` when unmeasured) and, for an agent, `outputs`: each `{type, payload: {filename, storageFilename, fileSize}}`, `imageGenerationCard` for an image and `PdfFileDownload` and the like for a file. `GET /v1/document/generated-files/{storageFilename}` answers the bytes, an HTML file as `text/html` with `Content-Disposition: attachment`, which `_file` takes where it would refuse the web UI's own page; `generatedFilesOf` keeps only a storage name of letters, digits, `_`, `.` and `-`.
- Embeds: `GET /v1/embed` lists each one's `uuid`, `enabled`, `chat_mode`, `workspace.name` and `chat_count`, but not its allowed sites or limits, so those are set only when it is made. `POST /v1/embed/new` takes `workspace_slug`, `chat_mode`, `allowlist_domains`, `max_chats_per_day` and `max_chats_per_session`, and answers `embed` or an `error`. `POST /v1/embed/{uuid}` changes `enabled` and `chat_mode`; `chat_mode` is only `chat` or `query`. An embed chat's `response` is JSON holding its `text`.
- The everythingllm host's cards are Markdown linked images: `[![title](https://<host>:8445/...)](<page>)`. The host draws them dark unless the address asks for `theme=light`; `CardImage` reads a `/_cards/` or `/_live/` card on the server's host through `themedCard` (`core/chat.dart`), which adds it in the light theme, while the card's identity (`appCardOf`, `browserCards`, `showApp`) keeps the address the answer gave. A page's card (`_cards/<name>.png?v=<hash>`) is a plain PNG whose address changes with what it shows. A live card (`_live/...`: a run's progress, a workspace's browser, a login request) is `multipart/x-mixed-replace; boundary=frame` while it runs, each part a whole PNG or JPEG with its own `Content-Length`, and a plain image once its run has ended. A watched live card keeps that workspace's browser from being stopped as idle. Its link goes to a page on the pages site or to the browser's take-over view on its own port, which needs a real browser. An app's card (`/_live/apps/<workspace>/<name>.png`, `isAppCard` in `core/chat.dart`) is one more live card. A linked one (`appCardOf`: the card, its page, the app's name from the description or else the file name, and the workspace's slug) opens its app read-only, since there is no API to change an app's data: `AppPanel` (`ui/chat/app_panel.dart`), on a phone as a sheet (a `SheetFrame`) with the name at 17, `App · <workspace>` under it, Open in the browser and Close at 44, and the live card large, or where there is `AppScope.appView` (Android) the app's own page in a web view (`AppWebViews`, `ui/chat/app_web_view.dart`, `webview_flutter`, imported by `main.dart` only), scripts on, the card over it until it loads and a link off its host handed to `openLink`, so its ticks and adds work, opened at `themedPage` (`?theme=light` or `dark`, which the card link passes on to the page and the page's client keeps its `prefers-color-scheme` rules to, so the page follows the app's theme, not the device's); `AppWebViews` keeps one page loaded out of sight, the newest shown or prefetched, and on a phone `MessageList` prefetches the page of the chat's newest app card (`ChatController.appCard`, from `appCardsIn` in `core/chat.dart`, finished answers only), so its sheet opens on the page at once; a prefetch never replaces a page on screen, and a page whose load failed is fetched again; elsewhere, in the browser panel's place (`ShellController.showApp`, `closeApp`, at `Sizes.browser`), framed by `SidePanel` with the kind beside the name (`aboutBeside`) and Open in the browser among its `actions`. Open in the browser opens the app's page through `openLink`. A drag down past 120 px, a tap on the scrim, Esc and Back close the sheet. - Doc comments state what a thing is or does, in plain sentences, with `[name]` references. Match that density in new code.
